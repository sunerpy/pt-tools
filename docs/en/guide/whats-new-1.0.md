# What's new in the 1.0 preview <Badge type="tip" text="1.0 preview" />

The 1.0 preview (versions such as `1.0.0-rc.N`; the first few previews were `0.49.0-rc.N`) adds seed boosting (brush tasks), IYUU cross-seeding, media library organising, the mobile app, remote access, the AI assistant and more on top of 0.48.0. This site documents the preview: pages marked "1.0 preview" and features marked "Preview" on the home page are only in the preview releases, not in the 0.48.0 stable release; the 1.0 stable release will include all of them.

The preview releases are for testing and are not recommended for production yet. See [Installing a preview release](./install.md#installing-a-preview-release) to install one, and back up the data folder before upgrading. The changes in each preview are listed under the Pre-release versions on [GitHub Releases](https://github.com/sunerpy/pt-tools/releases).

## Brushing and seeding

- [Seed boosting](./brush.md): pick new torrents from a site's free list by your conditions, delete them by seeding time, ratio, upload speed and other rules, and cap concurrent downloads and size; torrents with H&R follow the site's rules or the seeding requirement set in the site settings. M-Team tasks can read the general section, the adult section or both; each task keeps a [run history](./brush.md#run-history) of what every round added, deleted and skipped and why; [earnings](./brush.md#earnings-and-the-daily-report) can be viewed by day, week, month, quarter or year.
- [IYUU cross-seeding](./reseed.md): find torrents with the same data on other sites through IYUU, check the files, add them to the same downloader and start seeding only after verification reaches 100%; the data is stored once. Sites take part by switch; a round in progress can be [paused, stopped and continued](./reseed.md#rounds), and the next round carries on from one that stopped early; records can be filtered, retried, deleted and cancelled; [statistics](./reseed.md#statistics) show successes, failures, skips and IYUU requests by day, week, month, quarter, year or a custom range; IYUU requests get a minimum gap and a daily limit, and a rate limit is waited out for the time IYUU gives; round results can go to notification channels and into the daily report.
- [Torrent transfer](./torrent-transfer.md): move finished torrents to another downloader to keep seeding without touching the data files; a torrent leaves the source downloader only after verification reaches 100%, and transfers can run on a schedule by rules.
- [Downloader assistant](./downloader-assistant.md): find torrents the site has deleted, add missing site labels, and replace tracker addresses in bulk, each previewed before it runs.
- [qB-compatible entrance](./qbit-compat.md): tools that only talk to qBittorrent, such as MoviePilot, autobrr, Sonarr and Radarr, can treat pt-tools as one; the torrents they add still pass the disk space and site seeding capacity checks.

## Media library

- [Follow and subscribe](./media-subscribe.md): subscribe to a movie or follow one season of a series; pt-tools searches the sites and also downloads from RSS, picks releases by quality profile, upgrades to better versions, and turns Douban "want to watch" items into subscriptions. A followed series is searched when each episode airs and keeps to one release group and resolution (it waits rather than switching, and one episode can take another version); variety shows split into parts match too. Follow (追剧) on a search result starts from that torrent; every search records what it found and why it skipped a torrent; a finished season can roll over to the next; the bot has `/follow`, `/runs` and `/unlock`. Subscriptions and followed series accept title include and exclude words; when the release group stops, Edit (修改) [changes the locked version](./media-subscribe.md#version-lock) directly; filling missing episodes from a season pack downloads only the missing ones; a release group whose subtitles write the episode number as the issue [gets an episode-number rule automatically](./media-subscribe.md#variety-show-episodes) after its first download.
- [Media library organising](./media-library.md): finished movies and series are hard-linked into the library by naming templates, with NFO files and posters, and Emby, Jellyfin or Plex is told to scan; second-level categories, replacing older versions with the same name, watched folders, [organising a file or folder by hand](./media-library.md#organising-a-file-or-folder-by-hand) (with a different organise mode for that run if you like) and per-item scraping switches are available; plots, ratings, episodes and images can each come from a chosen source (TMDB, Douban, Bangumi, Fanart.tv, OMDb), the organise history shows each scrape's result, and titles can be rescraped.
- [Media recognition](./media-recognize.md): parse torrent titles and find the movie or series on TMDB (English or romanised torrent names are also compared with TMDB's aliases and translated titles), keep the IMDb and Douban IDs the site provides, correct wrong matches or add recognition words; the TMDB API and image addresses can be changed. Released builds have a TMDB API key built in, so you don't need to request one; you can still enter your own.

## Mobile app and APIs

- [Mobile app](./mobile-app.md): the Android app shows the overview, torrents, sites and subscriptions away from home, pauses, deletes and pushes torrents or manages subscriptions within the permissions given at pairing, and talks to the AI assistant; since 1.0.0-rc.28 its packages are published in the same Release as the server. The app can [edit followed series and brush tasks](./mobile-app.md#following-shows-brush-tasks-and-statistics-sharing), show brush earnings by period and make statistics posters; it uses black-and-white styling with four themes (Light, Dark, Warm, Graphite).
- [Remote access](./remote-access.md): pair by scanning the QR code in the web UI; the app tries a direct connection first and falls back to a relay. The connection is end-to-end encrypted and the relay only forwards. The built-in hosted relay is used by default; you can run your own relay or turn relays off and connect directly only.
- [API tokens](./api-tokens.md) and the [App API](../reference/app-api.md): scripts and clients reach `/api/app/v1/` with a token, reading or changing data within its scopes, without storing the web password.
- [MCP](./mcp.md): AI assistants in MCP clients such as Claude, Cursor and Cherry Studio can look at torrents, downloaders, site data, subscriptions and media libraries, recognise torrent titles, and make changes after you confirm them (including managing subscriptions and organising into the library); a change first returns a preview (before, after and impact). With the Config scope on the token they can also read and change pt-tools' configuration, and the built-in `pt-tools-config` skill explains how.

## Notifications and the AI assistant

- [AI assistant](./assistant.md): connect an OpenAI-compatible model (Groq and Google AI Studio are supported too) and ask in plain language in the web UI, the mobile app, Telegram or QQ to look up data, search and push torrents, manage subscriptions or organise into the library; every change needs your confirmation. The web page shows the thinking and tool calls (folded once the answer is done), lets you change the model and reasoning effort for each message, and takes images and text files. Confirmation cards list each item before and after and the possible impact; the input box shows the context usage, and at the threshold (80% by default) the earlier conversation is compacted into a summary; you can [have it change the configuration](./assistant.md#changing-the-configuration) (downloaders, sites, RSS, notification channels and most other settings; secrets are write-only); with Voltip connected you can [talk instead of typing](./assistant.md#voice-input).
- [More notification channels](./notify-channels.md): DingTalk and Feishu group bots, Bark, ServerChan and ntfy; "Recent notifications" lists RSS and background notifications, and delivery statistics show each source.
- [Notification delivery records](./chatops-quickstart.md#viewing-the-audit-log): every delivery of a background notification such as the daily report, sign-in or a followed series is recorded in the audit log, with the reason when it failed; on QQ and Telegram channels these notifications go to the recipient set in the channel settings.
- [ChatOps bindings](./chatops-telegram.md#generating-a-binding-code-and-linking): the bindings page lists each channel's bot status, where notifications go and who on the lists is linked; accounts on the lists can be linked from the web UI, and unused binding codes can be revoked.
- [Message templates](./notify-channels.md#message-templates): customize the title and body of each notification event; command replies and AI assistant replies can use templates too.
- [Custom webhook](./notify-channels.md#custom-webhook): set the request method, format and body template, start from presets such as Discord, Slack and Gotify, and judge success by the response content.

## Sites and data

- [Statistics and daily report](./user-stats.md): a snapshot is kept on each day a site's data is fetched, giving increments and trends for today, this week and this month; the daily report (off by default) can send the previous day's increments (or today's up to the send time) to the channels you choose.
- [Share image](./user-stats.md#exporting-a-share-image): five styles (Bento, Paper, Night, Wrapped and Receipt), each with two or three color schemes; the preview is the exported image. Masking keeps the first character of a name followed by a bar, and turns an icon into a block of its colors.
- [Daily sign-in](./site-login-monitoring.md#daily-sign-in): the Sign-in page under Sites shows whether each site is signed in today, with its switch, Sign in now and Sign in to all, two weeks of history, and the settings for the time window, AI and result notifications; the `/signin` command works too; Sign-in details list, day by day, how each site's sign-in went, whether it was direct or used AI, and how many AI calls and tokens it took. Sites such as HDArea and Rousi Pro use their own sign-in endpoints; captchas on HDSky and OpenCD and quiz questions on PTCHDBits and 52PT can be [handled by AI](./site-login-monitoring.md#captchas-and-quiz-questions-with-ai).
- [Inactivity reminders](./site-login-monitoring.md#inactivity-reminders): before a reminder is sent, a site whose last probe succeeded more than 30 minutes ago is probed again, so signing in with the browser just now no longer leads to a reminder based on a result from hours ago.
- [CookieCloud import](./cookiecloud.md): fetch the cookies your browser synced to your own CookieCloud server, decrypt them locally and write them to sites after a preview, or sync on a schedule; the browser extension can sync cookies on a schedule and upload them to CookieCloud encrypted.
- [Browser extension](./browser-extension.md): the popup's main page is My sites, listing only the sites with a cookie in the browser or enabled in pt-tools, each with its cookie and keep-alive status and Sync and Open on the row; Sync all and Open sites sit above the list, and the address, scheduled sync and CookieCloud moved to Settings at the top right. The list shows as soon as the popup opens while the connection is checked separately, instead of waiting several seconds. Sign-in cookies are recognized by format (the site's own set, NexusPHP's uid plus pass, or the single `c_secure_pass` of newer NexusPHP); when the format is not recognized the row shows Unverified, and on sync pt-tools first signs in to the site with those cookies and saves them only if that works. With Sync every site signed in on this browser (同步浏览器里登录着的全部站点) ticked, scheduled sync also pushes sites that are disabled in pt-tools, saving the cookie without enabling the site.
- [NAS installs](./install.md#nas): app definitions for 1Panel, Unraid and fnOS.
- [Site proxy](../configuration.md#site-proxy-in-global-settings): choose in Global settings which sites go through a proxy (all sites, only the selected ones, or all but the selected ones); a change takes effect when you save, without a restart. While it is off the environment variables apply as before, and RSS torrent downloads now follow the proxy set in them too.
- Site parsing: bonus, ratio and bonus per hour for CrabPT, GameGamePT, HDArea and OpenCD, and the ratio of many sites when it is below 1, are fixed; sites without an H&R seeding time in their rules can have one set in the site settings. OurBits text promotions, H&R and subtitles are recognized, PTTime gets its class requirements and free end times, BYR gets its class requirements and reads bonus per hour from the bonus page, PTerClub gets list subtitles, bonus per hour, seeding size and class requirements, PTCHDBits recognizes text promotions and their end times, counts H&R only on torrents marked H3 or H5, and gets bonus per hour and class requirements, the 50%, 2X and 30% promotions that PTTime, OurBits and HHCLUB show as text in torrent lists are no longer read as no promotion, sites such as DiscFan and TJUPT read list subtitles the way each site lays them out instead of with a generic rule, an infinite ratio always shows as ∞, seeding size adds up the "Size" column of the seeding list so a first row whose title contains "10bit" or "1940 Blu-ray" no longer produces thousands of PB, M-Team seeding and leeching counts and seeding size come from the endpoints its profile page uses (the old statistics endpoint now always returns 0), and seeding, leeching and unread message counts update when they drop to 0; site requests retry with exponential backoff after a temporary error such as a connection reset or timeout; since BYR's sign-in tokens now expire after 15 minutes and are reissued on use, pt-tools keeps using the reissued tokens and saves them, so it stays signed in. TJUPT is added; it requires tools that use your cookie to be registered on its forum first, so read the note in [Supported sites](../sites.md) before turning it on. HDDolby moved to `www.uhddolby.com` and is now called UHDDolby: it works with only the API key (the RSSKEY from the RSS page), the cookie is only used for bonus per hour and the new sign-in, free promotions and their end times come from the site's promotion fields (a time-limited free torrent used to read as 2X, and labels such as "official" as promotions), a two-step verification page met with the cookie is reported as such, and the trackers of torrents already in a downloader are replaced with the [downloader assistant](./downloader-assistant.md#replacing-trackers).

## Reliability and security

- [Free status](../configuration.md#global-settings): pushes that require free torrents use the free status read in the same run; an unknown status does not count as free, and a torrent without enough free time left is not pushed. A torrent whose free end time is unknown is not started automatically, and unfinished torrents can be paused or deleted a few minutes before the free period ends.
- [Auto-delete](./auto-cleanup.md): preview which torrents a run would delete, along with the protected ones and the protection rule each hits, and see the result of the last run on the page; torrents with H&R whose seeding requirement is unknown are protected; inactivity is judged by the time the downloader recorded for the last upload or download, not by the speed at the moment of the check.
- [Keeping torrents](./auto-cleanup.md#keeping-torrents): Keep (保留) and Unkeep (取消保留) torrents with one click in the torrent list on the Downloader page. Torrents with the `pt-tools-keep` tag are not deleted by auto-delete (including emergency cleanup), seeding competition, the deletion at the end of a free period or brush tasks; the keep tag, the protected tags and H&R protection apply the same way to all of these, and a protected torrent is paused instead of deleted when its free period ends. Brush task torrents are recognised by the task's records: when you delete a task, the torrents it leaves behind go to auto-delete by default, or you can keep them (adding `pt-tools-keep`); the ones handed back to you are handled by auto-delete's rules.
- [Seeding competition](./auto-cleanup.md#seeding-competition): merged into auto-delete as one of its deletion conditions; above the S/L limit a torrent is deleted or only paused, at the auto-delete check interval. It follows the protection rules like the other conditions, so it no longer deletes or pauses torrents a brush task is managing, torrents that have not met their H&R requirement, or torrents added less than the minimum keep time ago. A torrent competition paused is not paused again once you start it, and paused torrents are judged by the other deletion conditions too; deleting follows Delete the data files too. An installation that had only competition on (auto-delete off) gets auto-delete turned on at upgrade, acting on competition only: the check interval carries over, and the other deletion conditions, the free-period deletion and emergency cleanup are off.
- [Disk space protection](./auto-cleanup.md#disk-space-protection): new Emergency cleanup when below the minimum (空间低于下限时紧急清理), on by default as before the upgrade; with it off, low space only blocks pushes, with no extra deletions and no early check. When free space is checked before a push, a newly pushed torrent that the downloader already lists is counted once, by the remaining size the downloader reports, and no longer a second time by its full size, so a push is no longer refused for lack of space while there is enough; a pushed torrent the downloader never lists stops counting after 15 minutes.
- [RSS subscriptions](./rss-subscription.md): saving a site or syncing cookies from the browser extension keeps each RSS subscription's ID, so Download now (立即下载) in a notification sent before the edit still works and staged torrents stay with the subscription they belonged to; enabling or disabling a site in the site list no longer clears the filter rules attached to its RSS subscriptions.
- [Unfinished when freeleech ends](./rss-subscription.md#freeleech-eligibility-and-pausing): each RSS subscription chooses Do nothing, Pause or Delete, replacing the global Delete when freeleech ends (免费结束自动删除); installs that had it on get Delete on the subscriptions that paused at freeleech end, and torrents already waiting are handled as before the upgrade. The choice is recorded when a torrent is pushed, so changing it later only affects torrents pushed afterwards. Auto-delete's free-period fallback is renamed Delete other free torrents still unfinished after freeleech (其他免费种子免费过了没下完就删): it covers only torrents not set to Pause or Delete, is stopped only by the keep tag, the protected tags and H&R protection, and no longer waits for the minimum keep time.
- Credentials: site cookies are stored only encrypted, and plaintext left by older versions is removed on upgrade; a damaged key file is no longer overwritten, and pt-tools refuses to start when the key does not match the stored ciphertext.
- Upgrades: self-upgrade checks the downloaded file against the same version's `checksums.txt`; update checks no longer report older previews as new versions.
