# What's new in the 1.0 preview <Badge type="tip" text="1.0 preview" />

The 1.0 preview (versions such as `1.0.0-rc.N`; the first few previews were `0.49.0-rc.N`) adds seed boosting (brush tasks), IYUU cross-seeding, media library organising, the mobile app, remote access, the AI assistant and more on top of 0.48.0. This site documents the preview: pages marked "1.0 preview" and features marked "Preview" on the home page are only in the preview releases, not in the 0.48.0 stable release; the 1.0 stable release will include all of them.

The preview releases are for testing and are not recommended for production yet. See [Installing a preview release](./install.md#installing-a-preview-release) to install one, and back up the data folder before upgrading. The changes in each preview are listed under the Pre-release versions on [GitHub Releases](https://github.com/sunerpy/pt-tools/releases).

## Brushing and seeding

- [Seed boosting](./brush.md): pick new torrents from a site's free list by your conditions, delete them by seeding time, ratio, upload speed and other rules, and cap concurrent downloads and size; torrents with H&R follow the site's rules or the seeding requirement set in the site settings. M-Team tasks can read the general section, the adult section or both; each task keeps a [run history](./brush.md#run-history) of what every round added, deleted and skipped and why; [earnings](./brush.md#earnings-and-the-daily-report) can be viewed by day, week, month, quarter or year.
- [IYUU cross-seeding](./reseed.md): find torrents with the same data on other sites through IYUU, check the files, add them to the same downloader and start seeding only after verification reaches 100%; the data is stored once, and while the original torrent is there a cross-seed does not count towards the [site seeding capacity](./reseed.md#site-seeding-capacity) (刷流容量上限), so a site at its limit can still be cross-seeded. Sites take part by switch; a round in progress can be [paused, stopped and continued](./reseed.md#rounds), and the next round carries on from one that stopped early; records can be filtered, retried, deleted and cancelled; [statistics](./reseed.md#statistics) show successes, failures, skips and IYUU requests by day, week, month, quarter, year or a custom range; IYUU requests get a minimum gap and a daily limit, and a rate limit is waited out for the time IYUU gives; round results can go to notification channels and into the daily report.
- [Torrent transfer](./torrent-transfer.md): move finished torrents to another downloader to keep seeding without touching the data files; a torrent leaves the source downloader only after verification reaches 100%, and transfers can run on a schedule by rules.
- [Downloader assistant](./downloader-assistant.md): find torrents the site has deleted, add missing site labels, and replace tracker addresses in bulk, each previewed before it runs.
- [qB-compatible entrance](./qbit-compat.md): tools that only talk to qBittorrent, such as MoviePilot, autobrr, Sonarr and Radarr, can treat pt-tools as one; the torrents they add still pass the disk space and site seeding capacity checks.

## Media library

- [Follow and subscribe](./media-subscribe.md): subscribe to a movie or follow one season of a series; pt-tools searches the sites and also downloads from RSS, picks releases by quality profile, upgrades to better versions, and turns Douban "want to watch" items into subscriptions. A followed series is searched when each episode airs and keeps to one release group and resolution (it waits rather than switching, and one episode can take another version); variety shows split into parts match too. Follow (追剧) on a search result starts from that torrent; every search records what it found and why it skipped a torrent; a finished season can roll over to the next; the bot has `/follow`, `/runs` and `/unlock`. Subscriptions and followed series accept title include and exclude words; when the release group stops, Edit (修改) [changes the locked version](./media-subscribe.md#version-lock) directly; filling missing episodes from a season pack downloads only the missing ones; a release group whose subtitles write the episode number as the issue [gets an episode-number rule automatically](./media-subscribe.md#variety-show-episodes) after its first download. When anime numbers episodes in another ordering such as absolute numbers, choose the series' [TMDB episode group](./media-subscribe.md#episode-groups), and seasons and episodes in torrents and file names are converted to the default seasons before matching and organising; torrents pushed by subscriptions can go into [a folder named after the title](./media-subscribe.md#per-title-download-folders); a media library can set a downloader, save folder, category and tags that are [filled in](./media-library.md#download-settings-for-new-subscriptions) when you create a subscription for it (or Choose by type picks it), and fields you changed yourself stay when you switch libraries; film subscriptions can pick a media library too, and Choose by type shows which library it will use; before a push, [AI can review](./media-subscribe.md#review-by-ai-before-downloading) whether a candidate is the right title and skip it when not. Explore adds top rated, now playing, upcoming, on the air and airing today, can [find by country and genre](./media-subscribe.md#explore), and its anime calendar lists the anime airing on Bangumi day by day, opening the matching series found on TMDB.
- [Media library organising](./media-library.md): finished movies and series are hard-linked into the library by naming templates, with NFO files and posters, and Emby, Jellyfin or Plex is told to scan; second-level categories, replacing older versions with the same name, watched folders, [organising a file or folder by hand](./media-library.md#organising-a-file-or-folder-by-hand) (with a different organise mode for that run if you like) and per-item scraping switches are available; plots, ratings, episodes and images can each come from a chosen source (TMDB, Douban, Bangumi, Fanart.tv, OMDb), the organise history shows each scrape's result, and titles can be rescraped. Torrents a subscription pushed or counted towards it are organised as the subscription's item instead of being recognised from the torrent name; the item is picked in the order [manual, organised before, subscription, recorded at push, recognition](./media-library.md#which-files-are-organised), and organise history shows where it came from. A movie's [disc](./media-library.md#discs) (BDMV, VIDEO_TS) goes into the movie folder whole, and a movie's ISO is organised as a video file; copying uses copy-on-write on file systems such as Btrfs and XFS, taking no extra space; directory monitoring watches the folders in real time by default and organises a dropped item 2 minutes after it stops changing. Organise history shows why records failed and filters by that category, ticked records can be retried, rescraped or deleted together, and By title groups them by movie or season; when a torrent name can't be matched, you can [ask the AI](./media-library.md#asking-the-ai) to pick from TMDB's candidates and record its pick as a correction; secondary categories can sort short dramas by running time and title keywords, and the preview says which rule matched; organising by hand can browse folders to pick a file. A library you organised yourself can be [imported](./media-library.md#importing-an-existing-library): titles are matched from existing NFO files, IDs in folder names or the names themselves, the files stay where they are, subscriptions stop downloading them again, and neither upgrades nor deleting records delete imported files; cast names in the NFO can be in Chinese, and titles whose scraping is incomplete can be filled in weekly. When a torrent has no subtitles, pt-tools can [fetch them from the site](./media-library.md#site-subtitles) (NexusPHP sites; only Chinese ones when there are any; zip archives unpacked to their subtitles) or hand the video to [ChineseSubFinder](./media-library.md#chinesesubfinder).
- [Search by title](./torrent-search.md#search-by-title): while you type in Torrent search, the drop-down offers films and series from TMDB; pick one and every site is searched for that title, and Find releases (搜资源) on the Explore page opens the search with its title. Results are scored by quality profile (another profile can be picked for one search), copies of the same release on different sites are merged into one card, and each card says which episodes it would fill in, which are already downloading, why it does not fit the profile, and whether it is the version a subscription locked; the episode cells and filters show counts. A push carries the title, and library organising uses it. Keyword search results show what was parsed from each title too, with [filters](./torrent-search.md#filters) for resolution, source, release group and more.
- [Blocking](./torrent-search.md#blocking) and [waiting for free](./torrent-search.md#waiting-for-free): click Don't want (不要) to block a torrent you do not want (with an optional reason), and subscriptions stop picking it; a block made in search by title applies to that title, one made in keyword search to every subscription, and in follow details you can also delete the torrent from the downloader and add its release group to the title exclusions. For a torrent that is not free yet, click Wait for free (等免费), pick a downloader and how long to wait (up to 30 days): a background task checks the discount every 5 minutes and pushes the torrent, and tells you, only once it is free. Download → Wait for free (下载 → 等免费) changes the end time or cancels a wait.
- [Title details and the subscription calendar](./media-detail.md): one page per film or series with the TMDB details and rating, how many episodes of each season are in the library, the seeding torrents and their H&R, and the subscription; every episode's state (in library, downloading, waiting for the version, missing, not aired), with Find releases (搜资源) on a missing one opening search by title for that season; the torrents for the title, with whether each can be deleted under the auto cleanup protection rules and a way to block it; a title you no longer want can be [deleted in one go](./media-detail.md#deleting-a-title): library files, torrents (protected ones need a tick each, and torrents sharing data with others lose only the torrent) and the subscription, with a result for every step; the cast and recommendations. Explore, Follow and subscribe, Organise history and search by title all link to it. Media → Calendar (媒体 → 日历) shows by month or week when each subscribed episode airs and whether it is in the library; Today's updates (今日更新) in Subscription settings pushes the episodes airing today to your notification channels at a set time; the bot has `/today`, and the daily report gets a followed-show line.
- [Media servers](./media-library.md#media-servers): pt-tools regularly records which movies, shows and episodes Emby, Jellyfin and Plex have as an [index](./media-library.md#index): title details show how many episodes the server has, with Play in Jellyfin and a play button on each episode, and pt-tools warns when a title it organised is gone from the server, or when the daily check finds [library files missing](./media-library.md#missing-library-files); you can handle it (which opens the delete dialog) or ignore it. Episodes on the server can [count as in the library](./media-library.md#counting-server-episodes), so following does not download them again; with the [webhook](./media-library.md#webhook) on, new and removed items sync 2 minutes later and playback starting or stopping sends a [notification](./media-library.md#playback-notifications); Emby and Jellyfin can provide one user's [continue watching](./media-library.md#continue-watching).
- [Home page](./home-and-health.md): the web UI opens on the home page. At the top is the [NAS overview](./home-and-health.md#nas-overview): four value cards for the CPU, memory, network and storage of a host, with bars for the last 30 ticks, updated every 30 seconds; the data comes from System → [NAS monitoring](./nas-monitor.md) (系统 → NAS 监控): the local source reading the host pt-tools runs on (Linux), [TrueNAS](./nas-monitor.md#truenas) 25.04 or later connected with a read-only API key (storage pools, disk temperatures, alerts and apps), [Glances](./nas-monitor.md#glances) 4 run with Docker on Synology, fnOS, Unraid, OMV and other NAS systems (network, storage, disk temperatures and containers), and the experimental [Synology](./nas-monitor.md#synology) and [fnOS](./nas-monitor.md#fnos) sources (read the host, storage and disks directly with a DSM or fnOS account, fnOS also its containers, both with two-factor authentication; fnOS has been verified on a real device running fnOS 1.2.1000, Synology has not been verified on a real device), and you can choose which source the home page shows. Episodes airing and films released today get a card each saying whether they are in the library: play the ones in the library, Find releases (搜资源) for missing ones, See versions (看版本) for those waiting for the locked version; [Needs attention](./home-and-health.md#needs-attention) groups failed organising, unrecognised files, episodes waiting for a version, failed check-ins and login probes, titles removed from the media server, missing library files, failed backups and system check failures into a few kinds, each opening the right page with the filter applied, and titles removed from the server or missing files are handled or dismissed in a drawer on the home page; there are also continue watching, recently added, later this week and on the right downloaders (download and upload speeds with bars for the last few ticks, and each downloader), storage (the free space of each disk) and status (the system check, backups and the media server).
- [Media recognition](./media-recognize.md): parse torrent titles and find the movie or series on TMDB (English or romanised torrent names are also compared with TMDB's aliases and translated titles), keep the IMDb and Douban IDs the site provides, correct wrong matches or add recognition words; the TMDB API and image addresses can be changed. Released builds have a TMDB API key built in, so you don't need to request one; you can still enter your own.

## Mobile app and APIs

- [Mobile app](./mobile-app.md): the Android app shows the overview, torrents, sites and subscriptions away from home, pauses, deletes and pushes torrents or manages subscriptions within the permissions given at pairing, and talks to the AI assistant; since 1.0.0-rc.28 its packages are published in the same Release as the server. The app can [edit followed series and brush tasks](./mobile-app.md#following-shows-brush-tasks-and-statistics-sharing), show brush earnings by period and make statistics posters; it uses black-and-white styling with four themes (Light, Dark, Warm, Graphite).
- [Remote access](./remote-access.md): pair by scanning the QR code in the web UI; the app tries a direct connection first and falls back to a relay. The connection is end-to-end encrypted and the relay only forwards. The built-in hosted relay is used by default; you can run your own relay or turn relays off and connect directly only.
- [API tokens](./api-tokens.md) and the [App API](../reference/app-api.md): scripts and clients reach `/api/app/v1/` with a token, reading or changing data within its scopes, without storing the web password.
- [Servarr-compatible entrance](./servarr.md): Seerr can use pt-tools as its Radarr and Sonarr: a requested movie becomes a subscription and each requested season of a series a followed season, and the subscriptions' state and the files organised into the library go back to Seerr; deleting in Seerr removes only the subscription, never files or torrents. It is compatible with one fixed version of Seerr (commit `dca1af6a`).
- [MCP](./mcp.md): AI assistants in MCP clients such as Claude, Cursor and Cherry Studio can look at torrents, downloaders, site data, subscriptions and media libraries, recognise torrent titles, and make changes after you confirm them (including managing subscriptions and organising into the library); a change first returns a preview (before, after and impact). With the Config scope on the token they can also read and change pt-tools' configuration, and the built-in `pt-tools-config` skill explains how.

## Notifications and the AI assistant

- [AI assistant](./assistant.md): connect an OpenAI-compatible model (Groq and Google AI Studio are supported too) and ask in plain language in the web UI, the mobile app, Telegram or QQ to look up data, search and push torrents, manage subscriptions or organise into the library; every change needs your confirmation. The web page shows the thinking and tool calls (folded once the answer is done), lets you change the model and reasoning effort for each message, and takes images and text files. Confirmation cards list each item before and after and the possible impact; the input box shows the context usage, and at the threshold (80% by default) the earlier conversation is compacted into a summary; you can [have it change the configuration](./assistant.md#changing-the-configuration) (downloaders, sites, RSS, notification channels and most other settings; secrets are write-only); with Voltip connected you can [talk instead of typing](./assistant.md#voice-input).
- [More notification channels](./notify-channels.md): DingTalk and Feishu group bots, Bark, ServerChan and ntfy; "Recent notifications" lists RSS and background notifications, and delivery statistics show each source.
- [Notification delivery records](./chatops-quickstart.md#viewing-the-audit-log): every delivery of a background notification such as the daily report, sign-in or a followed series is recorded in the audit log, with the reason when it failed; on QQ and Telegram channels these notifications go to the recipient set in the channel settings.
- [ChatOps bindings](./chatops-telegram.md#generating-a-binding-code-and-linking): the bindings page lists each channel's bot status, where notifications go and who on the lists is linked; accounts on the lists can be linked from the web UI, and unused binding codes can be revoked.
- [Message templates](./notify-channels.md#message-templates): customize the title and body of each notification event; command replies and AI assistant replies can use templates too.
- [Custom webhook](./notify-channels.md#custom-webhook): set the request method, format and body template, start from presets such as Discord, Slack and Gotify, and judge success by the response content.

- [Statistics and daily report](./user-stats.md): a snapshot is kept on each day a site's data is fetched, giving increments and trends for today, this week and this month; the daily report (off by default) can send the previous day's increments (or today's up to the send time) to the channels you choose.
- [Share image](./user-stats.md#exporting-a-share-image): five styles (Bento, Paper, Night, Wrapped and Receipt), each with two or three color schemes; the preview is the exported image. Masking keeps the first character of a name followed by a bar, and turns an icon into a block of its colors.
- [Downloader seeding](./user-stats.md#downloader-seeding): the User Stats page and Overview in the mobile app list how many torrents each downloader is seeding right now and their size, to compare with the seeding size the sites report; a downloader that cannot be reached shows the reason.
- [Daily sign-in](./site-login-monitoring.md#daily-sign-in): the Sign-in page under Sites shows whether each site is signed in today, with its switch, Sign in now and Sign in to all, two weeks of history, and the settings for the time window, AI and result notifications; the `/signin` command works too; Sign-in details list, day by day, how each site's sign-in went, whether it was direct or used AI, and how many AI calls and tokens it took. - [Inactivity reminders](./site-login-monitoring.md#inactivity-reminders): before a reminder is sent, a site whose last probe succeeded more than 30 minutes ago is probed again, so signing in with the browser just now no longer leads to a reminder based on a result from hours ago.
- [CookieCloud import](./cookiecloud.md): fetch the cookies your browser synced to your own CookieCloud server, decrypt them locally and write them to sites after a preview, or sync on a schedule; the browser extension can sync cookies on a schedule and upload them to CookieCloud encrypted.
- [Browser extension](./browser-extension.md): the popup's main page is My sites, listing only the sites that are enabled in pt-tools, have automatic sync turned on, or whose sign-in cookies the browser recognizes (analytics and similar cookies left by opening a site without an account do not count), each with its cookie and keep-alive status and Sync and Open on the row; Sync all and Open sites sit above the list, and the address, scheduled sync and CookieCloud moved to Settings at the top right. The list shows as soon as the popup opens while the connection is checked separately, instead of waiting several seconds. Sign-in cookies are recognized by format (the site's own set, NexusPHP's uid plus pass, or the single `c_secure_pass` of newer NexusPHP); when the format is not recognized the row shows Unverified, and on sync pt-tools first signs in to the site with those cookies and saves them only if that works, otherwise the row shows the reason pt-tools gave. U2 is recognized by `nexusphp_u2`; SpringSunday sets `SPRINGID` even without signing in, so a recognized one also shows Unverified and is left to pt-tools to verify. With Sync every site signed in on this browser (同步浏览器里登录着的全部站点) ticked, scheduled sync also pushes sites that are disabled in pt-tools, saving the cookie without enabling the site.
- [NAS installs](./install.md#nas): app definitions for 1Panel, Unraid and fnOS.
- [Site proxy](../configuration.md#site-proxy-in-global-settings): choose in Global settings which sites go through a proxy (all sites, only the selected ones, or all but the selected ones); a change takes effect when you save, without a restart. While it is off the environment variables apply as before, and RSS torrent downloads now follow the proxy set in them too.

## Reliability and security

- [Free status](../configuration.md#global-settings): pushes that require free torrents use the free status read in the same run; an unknown status does not count as free, and a torrent without enough free time left is not pushed. A torrent whose free end time is unknown is not started automatically, and unfinished torrents can be paused or deleted a few minutes before the free period ends.
- [Auto-delete](./auto-cleanup.md): preview which torrents a run would delete, along with the protected ones and the protection rule each hits, and see the result of the last run on the page; torrents with H&R whose seeding requirement is unknown are protected; inactivity is judged by the time the downloader recorded for the last upload or download, not by the speed at the moment of the check.
- [Keeping torrents](./auto-cleanup.md#keeping-torrents): Keep (保留) and Unkeep (取消保留) torrents with one click in the torrent list on the Downloader page. Torrents with the `pt-tools-keep` tag are not deleted by auto-delete (including emergency cleanup), seeding competition, the deletion at the end of a free period or brush tasks; the keep tag, the protected tags and H&R protection apply the same way to all of these, and a protected torrent is paused instead of deleted when its free period ends. Brush task torrents are recognised by the task's records: when you delete a task, the torrents it leaves behind go to auto-delete by default, or you can keep them (adding `pt-tools-keep`); the ones handed back to you are handled by auto-delete's rules.
- [Seeding competition](./auto-cleanup.md#seeding-competition): merged into auto-delete as one of its deletion conditions; above the S/L limit a torrent is deleted or only paused, at the auto-delete check interval. It follows the protection rules like the other conditions, so it no longer deletes or pauses torrents a brush task is managing, torrents that have not met their H&R requirement, or torrents added less than the minimum keep time ago. A torrent competition paused is not paused again once you start it, and paused torrents are judged by the other deletion conditions too; deleting follows Delete the data files too. An installation that had only competition on (auto-delete off) gets auto-delete turned on at upgrade, acting on competition only: the check interval carries over, and the other deletion conditions, the free-period deletion and emergency cleanup are off.
- [Disk space protection](./auto-cleanup.md#disk-space-protection): new Emergency cleanup when below the minimum (空间低于下限时紧急清理), on by default as before the upgrade; with it off, low space only blocks pushes, with no extra deletions and no early check. When free space is checked before a push, a newly pushed torrent that the downloader already lists is counted once, by the remaining size the downloader reports, and no longer a second time by its full size, so a push is no longer refused for lack of space while there is enough; a pushed torrent the downloader never lists stops counting after 15 minutes.
- [RSS subscriptions](./rss-subscription.md): saving a site or syncing cookies from the browser extension keeps each RSS subscription's ID, so Download now (立即下载) in a notification sent before the edit still works and staged torrents stay with the subscription they belonged to; enabling or disabling a site in the site list no longer clears the filter rules attached to its RSS subscriptions.
- [Unfinished when freeleech ends](./rss-subscription.md#freeleech-eligibility-and-pausing): each RSS subscription chooses Do nothing, Pause or Delete, replacing the global Delete when freeleech ends (免费结束自动删除); installs that had it on get Delete on the subscriptions that paused at freeleech end, and torrents already waiting are handled as before the upgrade. The choice is recorded when a torrent is pushed, so changing it later only affects torrents pushed afterwards. Auto-delete's free-period fallback is renamed Delete other free torrents still unfinished after freeleech (其他免费种子免费过了没下完就删): it covers only torrents not set to Pause or Delete, is stopped only by the keep tag, the protected tags and H&R protection, and no longer waits for the minimum keep time.
- [Backup and restore](./upgrade.md#backing-up): the database is backed up every day (04:30 by default, the latest 7 kept, with the key included by default, optionally to another disk), and a Backup failed notification is sent when a backup does not complete; the first start after switching to a new version backs up once before migrating the database. Under Global settings → Backup and restore (备份与恢复) you can back up now, download, upload and [restore](./upgrade.md#restoring): a restore checks the backup and stages it, takes effect after a restart, and falls back to the current data if it cannot be applied. On the command line use `pt-tools db backup` and `pt-tools db restore`.
- [System check](./home-and-health.md#system-check): System → System check (系统 → 系统体检) checks TMDB, the sites' login probes, downloaders, media servers, path mappings, media libraries, disk space, NAS, this machine's clock, backups and the encryption key in one pass, saying how each stands and how to fix it, with the problems gathered under Needs attention (需要处理) and a Fix it (去处理) link on each; it changes no settings, and its result is kept and used by Needs attention and the status block on the home page.
- Credentials: site cookies are stored only encrypted, and plaintext left by older versions is removed on upgrade; a damaged key file is no longer overwritten, and pt-tools refuses to start when the key does not match the stored ciphertext.
- Upgrades: self-upgrade checks the downloaded file against the same version's `checksums.txt`; update checks no longer report older previews as new versions.
