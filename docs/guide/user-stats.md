# 数据统计与每日战报

「用户统计」页汇总各站的上传、下载、分享率、魔力与做种数据。pt-tools 在成功获取某站数据的当天给它存一份快照，用它算出每天、每周、每月的增量，在页面上画走势，也可以每天把当天的增量发到通知通道（每日战报，默认关闭）。

数据快照、增量与走势以及每日战报是 1.0 预览版加入的；「用户统计」页本身在 0.48.0 中已有。

## 数据从哪里来

- 每次成功获取某站的用户数据时，pt-tools 更新这个站点的数据，同时写入当天的快照；同一天获取多次只保留最后一次。
- 探测模式为「自动」的站点，登录状态探测每 6 小时左右获取一次用户数据，快照随之更新（见[站点登录状态与密钥备份](site-login-monitoring.md)）。
- 探测模式为「手动」或「禁用」的站点，只在登录 Web 界面或点击「同步」时更新，不另外定时访问。
- 快照按服务器时区分日（Docker 里由 `TZ` 决定），保留 400 天，更早的每天自动清理。
- 获取一个站点的数据要请求几页（首页、用户详情、魔力、做种列表）。站点定义里规定了请求间隔的（大多数 NexusPHP 站点），pt-tools 一页一页地取、中间隔开，避免几页同时请求招来 Cloudflare 质询；某一页连接被重置、超时或站点出错（5xx）时隔一会儿再试两次，遇到 Cloudflare 质询隔几秒再试一次。一个站点最多花 90 秒（线路慢时一页就要二三十秒），到时仍未取完的页算没取到。
- 还是有页面没取到、但用户名到手了时，这次照样算取到：没取到的几项沿用上一次的数据（最近访问时间按这次访问算），日志里记一行「Partial user info, kept previous values」，写明原因与沿用了哪几项。上传量、下载量没取到、又没有上一次的数据时，这次不保存。取不到用户名、登录失效时按失败处理，日志里一个站点一行「Failed to fetch user info」，`reason` 写明是 Cloudflare 质询、网络错误（连接被重置）、超时还是登录失效。

## 增量怎么算

- 某天的增量 = 当天快照 − 上一份快照。中间有几天没有快照时，这份增量覆盖的是这几天的总和，不做插值。
- 周期增量（今日、本周、本月）= 周期内最新一份快照 − 周期开始前最近的一份快照；周期开始前没有快照时，用周期内最早的一份。只有一份快照的站点算不出增量。
- 站点数据回退（站点重置统计、兑换魔力）时，那一项的增量按 0 计，不计入合计。

## 下载量的两种口径

- **下载量（计费）**：站点按免费、折扣等优惠折算以后、计入分享率的下载量。用户统计页、站点详情、每日战报、ChatOps 的 `/sites <站点>` 回复、手机 App、App API 与 MCP 里的下载量都是这个数，并且写明是计费口径（网页上是「计费」，ChatOps 回复里是 `Downloaded (billed)`）。
- **实际下载**：部分站点（例如 M-Team）另外报的实际传输量，没有按优惠折算。它和实际上传一起显示在用户统计页站点表的「实际传输」列（默认收起，在「列设置」里打开），以及站点详情「站点统计」卡的「实际上传 / 下载」一行；站点不报时没有这些数。
- 下载免费种子时实际下载会增长、计费下载量不变，这是正常的。判断有没有产生计费下载，看计费下载量与分享率的变化。
- 每日快照只存计费口径：增量、走势与每日战报里的下载都是计费下载量，实际下载没有历史记录。

刚安装或刚开始同步时没有历史快照，增量要等到第二天有了第二份快照才出现。

## 导出分享图

左侧导航「概览 → 数据导出」（或用户统计页工具栏的「导出分享」）把统计画成一张分享图。

- 样式：便当（默认，大小格子拼成一张图，信息最全）、素笺（纸底细线、衬线大数字）、夜幕（深色玻璃卡片，环形图画出上传与计费下载的比例）、回顾（一句话一个大数字，上传最多的三个站上领奖台）、小票（热敏小票、红章与条形码）。每个样式有两三种配色。选的样式与配色记在这个浏览器里，下次打开还是这一套。
- 预览就是导出的那张图。「下载图片」得到 2 倍大小的 PNG（宽 1280 像素）；「复制图片」复制到剪贴板，要用 HTTPS 或本机地址打开 pt-tools。手机上预览按屏幕宽度整体缩小，导出的图不受影响。
- 打码：默认打码站点名与站点图标，用户名可以另外打码。名字只留第一个字，后面换成遮盖条；图标换成同色的 4×4 色块。原文不在图里，没法还原。
- 逐站明细默认取前 10 个站点，也可以自己勾选；图上按上传从多到少排。周期增量可以选今日、本周或本月，尚无可比快照时图上不放。
- 图上的分享率是各站分享率的平均，与用户统计页的「平均分享率」是同一个数。

## 每日战报

在「系统设置」的「每日战报」里开启，设置发送时刻（默认 `22:00`，服务器时区）和接收通道。开启时至少要选一个通知通道，不会默认发到所有通道。

每天到了发送时刻，再错开一个本机固定、不超过 10 分钟的偏移（第一次用到时随机生成并保存，最晚当天 23:59），pt-tools 发一条当天的战报：

- 当天各站上传、下载（计费）、魔力的增量与合计，按上传排序最多列 10 个站点；
- 登录状态异常的站点（会话过期、密钥错误、被拦截、网络错误等）；
- 当天的签到结果（成功、已签、失败的站点数）；
- 数据回退、按 0 计入的站点。

战报只算已启用的站点；探测模式为「禁用」的站点不再探测，它残留的探测状态不算登录异常。没有今天之前的快照、算不出增量时，战报写明「暂无可比的数据」，不报一排 0。

同一天每个通道只发一次，重启也不会重发。通道处在自己的静默时段时，战报顺延到静默结束再发；发送失败按 1、5、30 分钟重试。服务在发送时刻之后、当天结束之前启动，会补发当天的战报；整个发送时刻到午夜都没在运行的那一天不补发，第二天的战报也只算第二天的增量。

## 接口

| 接口                                                    | 说明                                   |
| ------------------------------------------------------- | -------------------------------------- |
| `GET /api/v2/userinfo/history?site=<站点>&days=<1–400>` | 某站最近若干天每天的数据与增量         |
| `GET /api/v2/userinfo/summary?range=today\|7d\|30d`     | 各已启用站点在周期内的增量与合计       |
| `GET /api/v2/userinfo/trends?days=<1–60>`               | 各已启用站点最近若干天每天的增量与合计 |
| `GET` / `PUT /api/v2/userinfo/daily-report`             | 读写每日战报设置                       |

这些接口都要求登录。
