# IYUU 辅种

「下载 → IYUU 辅种」用 [IYUU](https://doc.iyuu.cn/) 找出其他站点上数据相同的种子，加进同一台下载器一起做种：数据只存一份，多个站点都算做种。默认关闭。

## 开启前

- 需要 IYUU 的 token，获取方法见 [IYUU 的说明](https://doc.iyuu.cn/)。
- 开启后，pt-tools 会把参与辅种的下载器里已下完种子的 info hash 发给 IYUU（`2025.iyuu.cn`）查询。
- token 用与站点 Cookie 相同的密钥加密保存在本机；页面和接口都不显示它，只显示「已设置」。

## 设置

| 项目         | 说明                                                                            |
| ------------ | ------------------------------------------------------------------------------- |
| 开启辅种     | 打开后按间隔自动运行；关闭时只能手动「立即运行」                                |
| IYUU token   | 不填就保留原来的；「清除」会删除 token 并关闭辅种                               |
| 运行间隔     | 1–168 小时，默认 12 小时                                                        |
| 每站每天最多 | 每个站点每天最多尝试多少个辅种（下载失败、核对不通过的也算），默认 20，最多 500 |
| 参与的下载器 | 不选就是全部启用的下载器                                                        |
| 参与的站点   | 不选就是全部「已在 pt-tools 配置、IYUU 也支持」的站点                           |

「站点」页列出 IYUU 支持的站点，以及它们在 pt-tools 里的情况：参与辅种、没有配置（pt-tools 认得这个站点，但尚未配置 Cookie 等）、没有选中、pt-tools 不支持。pt-tools 按站点地址的主机名和可注册域认站点，规则见[按 tracker 识别站点](downloader-assistant.md#按-tracker-识别站点)。

## 一轮辅种做什么

1. 读出参与的下载器里已经下完的种子（出错和正在校验的除外），把它们的 info hash 分批（每批 200 个）发给 IYUU 查询。
2. 对 IYUU 找到的每个种子：站点不在辅种范围、下载器里已经有、这个站点的这个种子以前试过、或者这个站点今天已经加满的，跳过。
3. 从站点下载种子文件（走站点的限速），核对 info hash 与 IYUU 给的一致，再核对文件列表与下载器里的原种子完全一样（每个文件的路径和大小都相同）。不一致的记为失败，以后也不再尝试；下载不到种子（站点暂时不可用等）的也记为失败，过 7 天再试。
4. 通过核对的，暂停加入同一台下载器，保存路径用原种子的，标签是站点 ID、`pt-tools-reseed` 和这个任务独有的 `pt-tools-reseed-<任务编号>`（任务结束后 qBittorrent 里的会被删掉，Transmission 里的留在种子上）。
5. 下载器校验到 100% 后开始做种，并在 pt-tools 里记下这个新种子（站点做种容量与自动删种都认得它）；校验不到 100% 就从下载器移除（数据保留），原种子不受影响。

第 4、5 步与[转移做种](torrent-transfer.md)用的是同一套任务：每台下载器同一时间只校验一个，pt-tools 重启后从中断的那一步接着做。辅种不会移除任何已有的种子。

IYUU 限流时，等待时间不超过 1 分钟就等一次再查，更久就停下这一轮，下一轮再来。运行中清除或更换 token 时，这一轮在查询下一批之前停下，不再用原来的 token 发送 info hash。

## 删除种子与共用的数据

辅种和原种子用的是同一份文件。自动删种（含紧急清理和「免费到期仍未下完的种子自动删除」）、做种竞争度监控、刷流删种和下载器助手的「删除失效种子」在要删数据时，先看下载器里有没有别的种子用着同一份数据：有就只删种子、保留数据；共用这份数据的种子一起删时，数据照常删除。pt-tools 按数据所在的路径判断，路径相同就算共用（qBittorrent 里不建子文件夹的多文件种子按文件判断）。

在下载器里，或者在 pt-tools 的种子列表里手动删除并选择同时删除数据时，文件会被删掉，共用这份数据的种子也会失去数据。

## 记录

「记录」页按最后一次尝试的时间列出最近 200 条：种子、站点与站内 ID、结果、原因和时间（过 7 天重试时更新原来那条）。结果是对应任务的进度（等待加入、校验中等），或者已辅种、已撤回（校验不到 100%，已从下载器移除）、失败（下载或核对没通过）。清除已结束的辅种任务时，任务的结果会先写进记录，记录里的结果不变；记录对应的任务被别的途径删掉时显示「任务已删除」。每一轮的汇总写在「设置」页底部的「上次运行」里。

## 接口

| 方法与路径                        | 说明                                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------------------------ |
| `GET`、`PUT /api/reseed/settings` | 读取或保存设置：`token` 以外整份保存，不认识的字段会被拒绝；`token` 不传时保留原来的，空串时清除 |
| `GET /api/reseed/sites`           | IYUU 站点与 pt-tools 站点的对照                                                                  |
| `POST /api/reseed/run`            | 在后台马上跑一轮，返回 202；正在运行时返回 409                                                   |
| `GET /api/reseed/records`         | 最近 200 条记录（按最后一次尝试的时间）与对应任务的状态                                          |
| `GET`、`DELETE /api/reseed/jobs`  | 辅种任务列表；DELETE 清除已结束的任务，任务结果先写进辅种记录                                    |

都要求登录。
