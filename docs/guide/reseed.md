# IYUU 辅种 <Badge type="tip" text="1.0 预览版" />

「下载 → IYUU 辅种」用 [IYUU](https://doc.iyuu.cn/) 找出其他站点上数据相同的种子，加进同一台下载器一起做种：数据只存一份，多个站点都算做种。默认关闭。页面分「统计」「设置」「站点」「轮次」「记录」五页，填了 token 以后先打开「统计」。

## 开启前

- 需要 IYUU 的 token：在 IYUU 官网 [iyuu.cn](https://iyuu.cn/) 点「开始使用」，用微信扫码登录后拿到，详见 [IYUU 的说明](https://doc.iyuu.cn/)。
- 开启后，pt-tools 会把参与辅种的下载器里已下完种子的 info hash 发给 IYUU（`2025.iyuu.cn`）查询。
- token 用与站点 Cookie 相同的密钥加密保存在本机；页面和接口都不显示它，只显示「已设置」。

## 设置

| 项目           | 说明                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 开启辅种       | 打开后按间隔自动运行；关闭时只能手动「立即运行」                                                                          |
| IYUU token     | 不填就保留原来的；「清除」会删除 token 并关闭辅种                                                                         |
| 运行间隔       | 1–168 小时，默认 12 小时                                                                                                  |
| 每站每天最多   | 每个站点每天最多尝试多少个辅种，默认 20，最多 500。按尝试的次数算：下载失败、核对没通过、手动重试的都算，删除记录不退名额 |
| 参与的下载器   | 不选就是全部启用的下载器                                                                                                  |
| 两次请求至少隔 | 两次请求 IYUU 之间至少隔几秒，默认 3 秒，0 是不隔，最多 300 秒                                                            |
| 每天最多请求   | 每天最多请求 IYUU 几次，默认 0（不限），最多 10000；到了上限，这一轮提前停下，第二天接着往下查                            |
| 每轮结果       | 每一轮结束以后推送结果：不推送（默认）、每一轮都推送、只在有变化时推送，见[通知](#通知)                                   |
| 接收通道       | 推送每轮结果的通知通道；推送开着时至少选一个                                                                              |
| 写进每日战报   | 每日战报里加一行今天的辅种，默认关闭                                                                                      |

参与辅种的站点在「站点」页用开关设置。

## 站点

「站点」页列出 IYUU 支持的站点，以及它们在 pt-tools 里的情况：参与辅种、没有配置（pt-tools 认得这个站点，但尚未配置 Cookie 等）、没有选中、pt-tools 不支持。pt-tools 按站点地址的主机名和可注册域认站点，规则见[按 tracker 识别站点](downloader-assistant.md#按-tracker-识别站点)。

已配置的站点每行有一个开关，上方有「全部开启」「全部关闭」：

- 默认是全部开启：所有已配置、IYUU 也支持的站点都参与，以后新配置的站点也自动参与。
- 关掉一个站点以后，只辅种开关打开着的站点；以后新配置的站点默认不参与，要在这里打开。点「全部开启」恢复为全部站点。
- 「全部关闭」以后一个站点也不辅种，一轮会停在「没有可以辅种的站点」。
- 没有配置的站点不能打开，先在「站点列表」里配置它。

## 一轮辅种做什么

1. 读出参与的下载器里已经下完的种子（出错和正在校验的除外），把它们的 info hash 分批（每批 200 个）发给 IYUU 查询。
2. 对 IYUU 找到的每个种子：站点不在辅种范围、下载器里已经有、这个站点的这个种子以前试过、或者这个站点今天已经加满的，跳过。
3. 从站点下载种子文件（走站点的限速），核对 info hash 与 IYUU 给的一致，再核对文件列表与下载器里的原种子完全一样（每个文件的路径和大小都相同）。不一致的记为失败，以后也不再尝试；下载不到种子（站点暂时不可用等）或读不到原种子的文件列表（下载器暂时连不上等）的也记为失败，过 7 天再试。站点上已经删了的种子（IYUU 的索引里还有，下载时 M-Team 回「種子未找到」、NexusPHP 站点的详情页写着「没有该ID的种子」）记为「站点已删除」，不算失败，以后也不再尝试。
4. 通过核对的，暂停加入同一台下载器，保存路径用原种子的，标签是站点 ID、`pt-tools-reseed` 和这个任务独有的 `pt-tools-reseed-<任务编号>`（任务结束后 qBittorrent 里的会被删掉，Transmission 里的留在种子上）。
5. 下载器校验到 100% 后开始做种，并在 pt-tools 里记下这个新种子（站点做种容量与自动删种都认得它）；校验不到 100% 就从下载器移除（数据保留），原种子不受影响。

第 4、5 步与[转移做种](torrent-transfer.md)用的是同一套任务：每台下载器同一时间只校验一个，pt-tools 重启后从中断的那一步接着做。辅种不会移除任何已有的种子。

一轮最多跑 30 分钟（暂停的时间不算），到时提前停下。运行中清除或更换 token 时，这一轮在查询下一批之前停下，不再用原来的 token 发送 info hash。

## 轮次

「轮次」页每一轮（定时、立即运行、继续或重试）记一条，写明怎么开始的、结果、用时与各项计数，保留最近 500 条、不超过 180 天。点开一轮看它的每一步（读了哪些下载器、查了哪几批、加入、失败、跳过与停下的原因）和这一轮的每一次尝试。pt-tools 退出时没跑完的轮次，下次启动时记为「被打断」。

正在跑的那一轮，页头有「暂停」「停止」：

- 暂停：正在下载的那一个做完以后停下，等你点「继续」；暂停的时间不算进 30 分钟。暂停超过 24 小时自动停止，以免忘了继续时定时的轮次一直无法运行。
- 停止：正在下载的那一个被打断，不记失败，以后照常再试；已经建好的辅种任务照常加入和校验。勾上「同时取消这一轮建的、尚未加入下载器的任务」时，这一轮结束以后一起取消它们。
- 继续：提前停下的轮次（被停止、到了时限、IYUU 限流、pt-tools 退出时没跑完）可以在「轮次」里点「继续」，只查这一轮没查完的部分；只有最近的那一轮能继续。下一次定时运行也会接着它往下查，跑到底以后下一轮再从头开始。

## IYUU 请求与限流

IYUU 推荐每天辅种一次，短时间内多次运行会被拒绝（辅种太频繁）。所有 IYUU 请求（读站点列表、报告站点、查询，包括「站点」页读站点列表）都按下面几条发：

- 两次请求之间至少隔「两次请求至少隔」的秒数（默认 3 秒）。
- 今天的请求到了「每天最多请求」的次数时不再请求，这一轮提前停下，第二天接着往下查。
- IYUU 回「请求太频繁」（HTTP 429）时，按它给的 `Retry-After` 与 `X-RateLimit-Reset` 里晚的那个冷却，最长 24 小时。冷却不超过 1 分钟时等一下再查，更久就停下这一轮。冷却期间不跑定时轮次，「立即运行」「继续」会被拒绝并写明到什么时候；更换 token 以后不再冷却。

「设置」页的运行情况里写着今天各接口请求了几次、冷却到什么时候、上一次限流的情况；「轮次」里每一轮也写着请求了几次。

## 删除种子与共用的数据

辅种和原种子用的是同一份文件。自动删种（含紧急清理和「免费到期仍未下完的种子自动删除」）、做种竞争度监控、刷流删种和下载器助手的「删除失效种子」在要删数据时，先看下载器里有没有别的种子用着同一份数据：有就只删种子、保留数据；共用这份数据的种子一起删时，数据照常删除。pt-tools 按数据所在的路径判断，路径相同就算共用（qBittorrent 里不建子文件夹的多文件种子按文件判断）。

在下载器里，或者在 pt-tools 的种子列表里手动删除并选择同时删除数据时，文件会被删掉，共用这份数据的种子也会失去数据。

## 记录

「记录」页按最后一次尝试的时间从新到旧列出每一条记录（每页 20 条）：种子、站点与站内 ID、结果、原因和时间（过 7 天重试时更新原来那条）。可以按结果、站点筛选，按种子名或 info hash 搜索。

结果是对应任务的进度（等待加入、校验中等），或者已辅种、已撤回（校验不到 100%，已从下载器移除）、失败（下载或核对没通过）、已取消、站点已删除（站点上已经没有这个种子）、任务已删除（记录对应的任务被别的途径删掉了）。清除已结束的辅种任务时，任务的结果会先写进记录，记录里的结果不变。

- 重试：失败、站点已删除、已撤回、已取消和任务已删除的记录可以重试，一次最多 100 条。重试在后台跑一轮（「轮次」里记为重试），不查 IYUU，用记录里的站点、站内 ID 与 info hash 重新下载、核对；不看站点开关和「以前试过」，但占「每站每天最多」的名额，名额用完的跳过；原种子已经不在下载器里的也跳过。重试的轮次不改「上次运行」，也不影响定时运行的间隔。
- 删除：任务尚未结束的不能删，一次最多 500 条。删除以后，这些种子在以后的轮次里会再试一次；今天已经用掉的名额和统计不变。
- 取消：还在等待加入下载器的任务可以取消，已经加入的不能取消。

每一轮的汇总还写在「设置」页的「上次运行」里，旁边的「下次运行」写明下一轮大约什么时候（开着、有 token 时按间隔，到点以后在下一次检查时跑）。

## 统计

「统计」页的范围有日、周、月、季、年与自定义：

| 范围   | 看多久                                                                   |
| ------ | ------------------------------------------------------------------------ |
| 日     | 最近 30 天                                                               |
| 周     | 最近 12 周                                                               |
| 月     | 最近 12 个月                                                             |
| 季     | 最近 8 个季度                                                            |
| 年     | 最近 5 年                                                                |
| 自定义 | 选开始和结束的日期，最长 5 年：62 天以内按天分段，一年以内按周，更长按月 |

- 顶部的数字带：成功、失败（含撤回）、站点已删除、建成任务、跳过与 IYUU 请求，每格的小柱子是最近 7 段。
- 柱状图每根柱子是一段里成功的辅种，读数写这一段的建成、失败、站点已删除、跳过与 IYUU 请求；「明细」把每一段列成表，新的在前。
- 「按站点」列出每个站点的建成、成功、失败、站点已删除与跳过；「跳过的原因」分开写下载器里已经有、已经尝试过、今天这个站点已经加满、站点不在辅种范围与已有进行中的任务；「IYUU 请求」写今天、这个范围与最近一次的请求。

建成、失败、站点已删除与跳过按开始尝试的那一天算，成功、撤回按任务完成的那一天算；按服务器的时区分段，周从周一开始。每一轮都会重新查一遍，同一个种子在每一轮都算一次跳过。升级到这个版本时，以前的辅种记录按记录的时间近似补进统计；跳过与 IYUU 请求从升级以后开始统计。尝试的明细保留 5 年。

## 通知

「设置」里的「每轮结果」选了「每一轮都推送」或「只在有变化时推送」时，每一轮结束以后发一条通知到选中的通道：标题写轮次、结果与怎么开始的（例如「辅种：第 12 轮完成（定时）」），正文写查询、找到、加入、失败、站点已删除与跳过的个数、用时与请求 IYUU 的次数；提前停下的轮次还写明可以继续。正文只有计数与状态，不列种子名。

- 「有变化」是这一轮加入了辅种、有失败，或者没跑完（部分出错、提前停下、被停止、未能开始）。
- pt-tools 退出时被打断的轮次不发。重试的轮次照同一个设置发。
- 同一轮只发一次；通道在静默时段里时顺延到静默结束；每一次投递记在[操作审计](chatops-quickstart.md#查看审计日志)里（「辅种结果」）。
- 选中的通道停用或删除以后不会改发给别的通道；保存设置时选中的通道必须都还在。

消息模板与自定义 Webhook 里这个事件是 `reseed.round`（「辅种结果」），变量见[消息模板](notify-channels.md#消息模板)。

「写进每日战报」打开以后，[每日战报](user-stats.md)里加一行「🌱 今日辅种：建成 x · 成功 y · 失败 z · 站点已删除 w」，数字与统计页同一个算法（失败含撤回，不写跳过）；当天没有这些数时不写。每日战报本身要先在「全局设置」里开启。

## 升级与回退

升级到这个版本以后有几处行为变了：参与的站点改在「站点」页用开关设置；每天的名额按尝试的次数算（删除记录不再腾出名额）；停止、到了时限或退出时正在下载的种子不再记成失败；提前停下的轮次由下一轮接着查；IYUU 冷却期间不跑定时轮次、手动运行会被拒绝。

回退到旧版本时这些功能没有了，辅种照原来的方式运行（按站点名单工作）。旧版本把空的站点名单当成全部站点，所以「全部关闭」以后回退会变成辅种全部站点：回退前先在「站点」页打开要辅种的站点。

## 接口

| 方法与路径                                     | 说明                                                                                                                                                                                        |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`、`PUT /api/reseed/settings`              | 读取或保存设置，不认识的字段会被拒绝；`token` 不传时保留原来的，空串时清除；`site_names`、`iyuu_min_interval_seconds`、`notify_mode`、`notify_channel_ids`、`daily_report` 不传时保留原来的 |
| `GET /api/reseed/sites`                        | IYUU 站点与 pt-tools 站点的对照                                                                                                                                                             |
| `PUT /api/reseed/sites`                        | `{"selected": true}` 全部开启，`false` 全部关闭                                                                                                                                             |
| `PUT /api/reseed/sites/{站点}`                 | `{"selected": true}` 打开一个站点，`false` 关掉                                                                                                                                             |
| `POST /api/reseed/run`                         | 在后台马上从头跑一轮，返回 202 与轮次编号；正在运行时返回 409，IYUU 冷却中或到了每天的上限时返回 429                                                                                        |
| `GET /api/reseed/runs`                         | 轮次列表（新的在前，`page`、`page_size`）                                                                                                                                                   |
| `GET /api/reseed/runs/{编号}`                  | 一轮的详情与步骤；`GET …/attempts` 是这一轮的尝试                                                                                                                                           |
| `POST /api/reseed/runs/{编号}/pause`、`resume` | 暂停、继续正在跑的那一轮                                                                                                                                                                    |
| `POST /api/reseed/runs/{编号}/stop`            | 停止正在跑的那一轮；`{"cancel_pending": true}` 时一起取消这一轮尚未加入下载器的任务                                                                                                         |
| `POST /api/reseed/runs/{编号}/continue`        | 接着最近一个提前停下的轮次往下查，返回 202 与新轮次的编号                                                                                                                                   |
| `GET /api/reseed/records`                      | 记录（按最后一次尝试从新到旧）与对应任务的状态；`result`、`site`、`q`、`page`、`page_size`                                                                                                  |
| `POST /api/reseed/records/retry`、`delete`     | `{"ids": [...]}` 在后台重试（返回 202 与轮次编号）或删除选中的记录                                                                                                                          |
| `POST /api/reseed/records/{编号}/cancel`       | 取消记录对应的、还在等待加入下载器的任务                                                                                                                                                    |
| `GET /api/reseed/stats`                        | 统计：`granularity`（day、week、month、quarter、year）加 `periods`，或者自定义的 `from`、`to`（YYYY-MM-DD，含两头）                                                                         |
| `GET`、`DELETE /api/reseed/jobs`               | 辅种任务列表；DELETE 清除已结束的任务，任务结果先写进辅种记录                                                                                                                               |

都要求登录。
