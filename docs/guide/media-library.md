# 整理入库 <Badge type="tip" text="1.0 预览版" />

pt-tools 能把下载完的电影与剧集放进媒体库：先识别出是哪部片，再按媒体库的命名模板放到库目录里（默认用硬链接，不多占空间，种子照常做种），写好 NFO 与海报，通知 Emby、Jellyfin 或 Plex 扫描，最后发一条入库通知。

设置在「媒体 → 媒体库」，结果在「媒体 → 整理历史」。识别要用 TMDB：发布的版本内置了 TMDB API Key，不用填；自己从源码编译的要先在[媒体识别](media-recognize.md#tmdb-api-key)里填。

## 准备目录

pt-tools 要能读到下载目录，也要能写媒体库。直接装在机器上时一般不用改什么；在 Docker 里运行时，要把两个目录都挂进 pt-tools 的容器。

用硬链接时，下载目录与媒体库必须在同一个文件系统上。Docker 里最稳妥的做法是挂载它们共同的上级目录，作为同一个卷：

```yaml
services:
  pt-tools:
    volumes:
      - /mnt/data:/data # 下载目录在 /mnt/data/downloads，媒体库在 /mnt/data/media
```

分开挂成 `/downloads` 与 `/media` 两个卷时，即使宿主机上是同一块盘，容器里硬链接也会失败。

下载器与 pt-tools 看到的路径不同时（比如两者在不同的容器里），在「路径映射」里添加：下载器里的 `/downloads` 在 pt-tools 里是哪个目录。按路径分段取最长的匹配，`/data` 不匹配 `/database`。路径相同时不用加。

## 媒体库

每个媒体库收一类条目。电影和剧集各建一个；想把动画单独放时，再建一个勾选「只收动画」的库（TMDB 类型里有「动画」的条目优先进这种库，没有这种库时进普通的库）。同类型有几个库时用排在前面的那个。

| 项目     | 说明                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------- |
| 类型     | 电影或剧集；勾选「只收动画」时只收动画                                                                |
| 库目录   | pt-tools 里看到的路径（绝对路径）                                                                     |
| 整理方式 | 硬链接（默认）、复制、软链接、移动，见下表                                                            |
| 命名模板 | 留空用默认模板，见[命名模板](#命名模板)                                                               |
| 刮削     | 写 NFO 与图片，写哪几样、图片用哪种语言、数据来源见[刮削](#刮削)；交给媒体服务器自己刮时关掉          |
| 覆盖     | 打开后每次整理都重写 NFO 与图片；关闭时已经有的不动                                                   |
| 同名文件 | 库里已经有 pt-tools 放的旧版本时替不替换，见[同名文件](#同名文件)                                     |
| 二级分类 | 勾选「按二级分类放进子目录」时放进「库目录/分类/…」，见[二级分类](#二级分类)                          |
| 下载设置 | 新建订阅时带出的下载器、保存目录、分类与标签，见[新建订阅时带出的下载设置](#新建订阅时带出的下载设置) |

| 整理方式 | 说明                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 硬链接   | 不多占空间，种子照常做种；下载目录与媒体库要在同一个文件系统上           |
| 复制     | 跨分区也能用；先写临时文件，复制完再改名。多占一份空间，见下文的写时复制 |
| 软链接   | 不占空间；媒体服务器要能用同一个路径读到下载目录，删种后链接失效         |
| 移动     | 文件搬进库里，种子不能再做种；只整理已暂停的种子                         |

移动时删不掉源文件（例如下载目录只读）：库里放好的那份照样记成已整理，方式按实际的记成复制（跨文件系统）或硬链接，写明源文件留在下载目录里，需要时自己删掉。

复制时先试写时复制（reflink，Linux 上下载目录与媒体库在同一个支持它的文件系统上，例如 Btrfs、XFS）：库里这份和源文件共用磁盘上的数据，不多占空间，之后改了哪一边才各自占用；整理方式仍是复制，整理记录里写明「复制用了写时复制」。文件系统不支持、跨文件系统或在别的系统上时照常逐字节复制。

编辑媒体库时点「检查」：确认库目录存在、可写；用硬链接时，再在每条路径映射的 pt-tools 路径里建一个文件、试着硬链接到库目录，确认在同一个文件系统上。试建的文件检查完就删掉。

### 新建订阅时带出的下载设置

媒体库里可以设下载器、保存目录、分类与标签，都可以空着。在「追剧与订阅」里新建订阅时，选了这个库，或者「按类型自动选」选到这个库，这几项会填进订阅的表单，输入框下面写明来自哪个库，保存前可以改。

- 只在新建订阅时，由网页的订阅弹窗和[手机 App](mobile-app.md#追剧刷流与统计分享) 的追剧编辑页带出。已有的订阅不变；保存与推送订阅时也不补。机器人、豆瓣想看、Servarr、AI 助手建的订阅不带出。
- 自己改过的项（输入、清空、选了别的）换库也不变，旁边的「换成媒体库「X」的」恢复成库的值。来自库的项换库时跟着换，新库没设的项清空。
- 修改已有的订阅时不自动带出：换了库以后出一条「套用「X」的下载设置」，点了才换。
- 库里设的下载器停用了或删了时不带出它，推送用设置里的默认下载器，表单里写明原因。下载器删了以后再编辑这个库，下载器显示「不指定」，保存时改成不指定。
- 保存目录是下载器里看到的目录，不是库目录。qBittorrent 的默认种子管理模式是「自动」时，种子按分类的目录放（没有分类时放默认目录），保存目录不起作用；订阅设置里开了[按条目建子目录](media-subscribe.md#按条目建子目录)时，pt-tools 让 qBittorrent 照保存目录放。
- 打开了自动整理或定期扫描、这几项不在[整理的范围](#触发方式)里时，编辑媒体库时提醒：照这样推送的种子下完不会自动整理。

## 命名模板

模板用 Go 的 text/template 写，算出库里的相对路径，不写扩展名（整理时自动加上）。默认模板 Emby、Jellyfin 与 Plex 都认。

电影的默认模板：

```text
{{.Title}}{{if .Year}} ({{.Year}}){{end}}/{{.Title}}{{if .Year}} ({{.Year}}){{end}}{{if .Quality}} - {{.Quality}}{{end}}
```

示例：`奥本海默 (2023)/奥本海默 (2023) - 2160p BluRay HDR10 H.265.mkv`。

剧集的默认模板：

```text
{{.Title}}{{if .Year}} ({{.Year}}){{end}}/Season {{.Season}}/{{.Title}} - {{.SeasonEpisode}}{{if .EpisodeTitle}} - {{.EpisodeTitle}}{{end}}
```

示例：`最后生还者 (2023)/Season 1/最后生还者 - S01E02 - 感染.mkv`。

编辑框上面有几个预设：目录名里带上 TMDB 编号时，Emby 写成 `[tmdbid=编号]`，Jellyfin 写成 `[tmdbid-编号]`，Plex 写成 `{tmdb-编号}`。改模板时下面会显示示例渲染的结果，写错时写明原因。

| 变量                                                                            | 说明                                                |
| ------------------------------------------------------------------------------- | --------------------------------------------------- |
| `.Title`、`.OriginalTitle`                                                      | 标题（TMDB，按媒体识别里设置的语言）与原名          |
| `.Year`                                                                         | 年份；剧集是首播年份                                |
| `.TMDBID`、`.IMDbID`                                                            | TMDB 与 IMDb 编号                                   |
| `.Season`、`.Episode`                                                           | 季与集                                              |
| `.SeasonEpisode`                                                                | `S01E02`，一个文件里有多集时 `S01E02-E03`           |
| `.EpisodeTitle`                                                                 | 这一集的标题（TMDB 有时才有）                       |
| `.Quality`                                                                      | 分辨率、来源、HDR、编码连在一起                     |
| `.Resolution`、`.Source`、`.VideoCodec`、`.HDR`、`.Audio`、`.Group`、`.Edition` | 分辨率、来源、视频编码、HDR、音轨、制作组、版本说明 |

`pad` 把数字补零，比如下面的模板写出 `最后生还者/Season 01/最后生还者 S01E02.mkv`：

```text
{{.Title}}/Season {{pad .Season 2}}/{{.Title}} {{.SeasonEpisode}}
```

变量里路径不能用的字符（`\ / * ? " < > |`）换成空格，冒号换成 `-`；每一级去掉首尾的空格与点，空的一级跳过，每一级最多 200 字节。算出的路径不会跑到库目录外面。

## 二级分类

媒体库勾选「按二级分类放进子目录」以后，条目先按规则分类，再放进「库目录/分类/」下面，例如 `电影/华语电影/让子弹飞 (2010)/…`、`剧集/欧美剧/最后生还者 (2023)/Season 1/…`。规则在媒体库页的「二级分类」里，电影与剧集各一组：

- 从上往下取第一条对得上的；都对不上时直接放进库目录。
- 一条规则可以按类型、原始语言、出品国家或地区分：几个条件都要满足，一个条件里选了几个时满足其中一个就行；条件都不填的那条收下前面都对不上的。
- 还可以按片长与标题关键字分（适合短剧）：片长（分钟，剧集按一集）不超过多少，或者种子名、站点上的标题里有其中一个关键字。这两项算一个条件里的「或」，和别的条件仍要都满足；片长填 0 是不看片长，TMDB 上没写片长时只看关键字。
- 原始语言写 ISO 639-1 代码（`zh`、`ja` 等，TMDB 把粤语记作 `cn`），国家或地区写 ISO 3166-1 代码（`CN`、`US` 等）；列表里没有的可以直接输入。
- 「填入常用分类」填的分类大体和 MoviePilot 默认的一样：电影分动画电影、华语电影、外语电影；剧集分国漫、日番、纪录片、儿童、综艺、短剧、国产剧、欧美剧、日韩剧、未分类。短剧是一集不超过 15 分钟、或者标题里有「短剧」的剧集，排在按类型分的几条后面，一集十几分钟的动画、儿童节目先进它们自己的分类。

分类名称就是目录名，不能有 `/ \ : * ? " < > |`。改了规则或开关只影响之后整理的文件，已经在库里的不动。剧集的 NFO、海报与 Logo 写在分类目录下的剧集目录里。整理入库的预览里会写明放进哪个分类、对上了第几条规则和对上的条件（例如「对上第 6 条「短剧」：片长 8 分钟（不超过 15 分钟）」）；都没对上时写明放在库目录里。按规则分要用 TMDB 的详情（电影的出品国家或地区、片长只在详情里），详情取不到时这次不整理，过一会儿自动再试。

## 同名文件

同一部电影或同一集换了版本（例如先下了 1080p、后来又下了 2160p），整理出的文件名一样时，库里那个位置已经被旧版本占着。媒体库的「同名文件」决定怎么办：

| 选项             | 说明                                   |
| ---------------- | -------------------------------------- |
| 不替换（默认）   | 留着旧版本，新的这个记成跳过，写明原因 |
| 新文件更大时替换 | 新文件比旧版本大才换                   |

只替换 pt-tools 之前放进这个库的同一部电影（同一集）的文件：按整理记录与文件编号确认还是当初放的那个。用户自己放的、换过的、[导入的已有文件](#导入已有的媒体库)、移动整理的（库里唯一的一份）一律不替换，媒体库用移动整理时也不替换。替换时新文件先放到旁边的临时名，旧文件挪到旁边的备份名并确认是旧记录放的那个，再把新文件放到原位置，写好整理记录以后才删掉旧文件：哪一步失败都会把旧文件放回原处，pt-tools 中途退出时下次启动会把没做完的撤回；旧版本的字幕与同名的 NFO、截图换成新的，目录里的海报等留着，旧的整理记录标成「已删除」并写明换成了什么。下载目录里的文件都不动。库目录所在的文件系统既不支持硬链接、也不支持不覆盖的改名时（少数网络存储），不替换并写明原因。

只按大小换：换下来的小的旧版本再整理（不管是自动还是手动）时不会把大的换回去，记成跳过；要换回去，先在整理历史里删掉新版本的记录（连库里的文件），再整理旧的。命名模板里带画质时（电影的默认模板就带），不同版本的文件名不同，不会撞上，两个版本都会留在库里；只想留一个时从模板里去掉画质，或者用订阅的洗版。

## 哪些文件会整理

- 视频文件：mkv、mp4、m4v、avi、ts、m2ts、mts、mov、wmv、flv、rmvb、rm、webm、mpg、mpeg。
- 跳过：Sample、Trailers、Featurettes、Extras、SPs、花絮、特典这类目录里的文件，文件名以 sample、trailer 结尾的，NCOP、NCED 片头片尾，以及小于「视频最小体积」（默认 50 MB）的。Specials 目录里的是第 0 季的正片，照常整理。
- ISO 镜像：电影的 ISO 当作一个视频文件整理（按视频文件的规则命名，扩展名是 `.iso`），能不能播放取决于媒体服务器与客户端；剧集里的 ISO 不整理，每个 ISO 记一条跳过的记录。
- 原盘（BDMV、VIDEO_TS 目录）：电影的原盘整张放进电影目录，见[原盘](#原盘)。
- 字幕（srt、ass、ssa、sub、idx、sup、vtt）跟着视频一起整理（花絮、样片目录里的不算），按文件名加上语言后缀：简体 `zh-CN`、繁体 `zh-TW`、中文 `zh`、英文 `en`、日文 `ja`、韩文 `ko`。种子里有几个视频时，按文件名前缀或季集分给对应的视频。
- 剧集的季与集从每个文件名里读，也套用[识别词](media-recognize.md#识别词)（集数偏移同样生效）；只有一个文件的种子读种子名。

整理时按这个顺序定条目，预览与整理历史里写明用的是哪一种：

1. 手动整理时填的 TMDB 编号（「手动指定」）；
2. 之前整理这些文件时用的条目（「沿用之前整理用的条目」）；
3. 订阅推送或算进订阅的种子：订阅的条目（「按订阅的条目」），不再识别；
4. pt-tools 推送时记下的条目（「按推送时说明的条目」）：订阅推送的种子都记着，订阅删了以后照样按它整理；
5. 以上都没有时识别：用种子名（站点标题不同时作为副标题），有站点给的 IMDb 编号时优先按编号查找。

订阅或推送时说明的条目在 TMDB 上找不到了（被合并、删除）时改成识别，整理记录里写明。季与集仍从每个文件名里读，不用订阅的季。追剧选了[剧集组](media-subscribe.md#剧集组)时，这部剧的文件名里的季集先按剧集组换成 TMDB 默认的季集再命名与刮削，剧集组里没有的集按文件名里的季集，整理记录里写明；读不到剧集组时这次不整理，稍后重试。

## 原盘

电影的蓝光原盘（BDMV 目录）与 DVD（VIDEO_TS 目录）整张放进电影目录：

- 原盘根目录（BDMV、VIDEO_TS 的上一级）里的原盘目录（BDMV、CERTIFICATE、AACS、BDSVM、VIDEO_TS、AUDIO_TS）按原来的相对路径放进命名模板算出的电影目录，例如 `奥本海默 (2023)/BDMV/STREAM/00001.m2ts`。根目录里别的文件（nfo、图片、样片）不放进库，预览里列在「没选上的文件」里。
- 整理方式同视频文件：硬链接、复制、软链接逐个文件放；移动时同样只整理已暂停的种子，移完删掉下载目录里移空了的原盘目录。中途失败时撤回这次放进去的文件（移动的挪回原处），记成失败。
- 刮削在电影目录里写 `movie.nfo`、`poster.jpg`、`fanart.jpg` 等（Jellyfin、Emby、Kodi 读电影目录里的 `movie.nfo`）；通知媒体服务器扫描电影目录。
- 一张原盘一条整理记录：源路径是原盘根目录，目标是电影目录，大小是放进库的文件的合计，整理历史里写明「原盘 N 个文件」。删除记录（连库里的文件）与订阅洗版时逐个按文件编号确认是当初放的才删，最后删空目录。
- 电影目录已经存在、里面有别的文件（例如这部电影的另一个版本）时不放进去，记成跳过；原盘不参与「同名文件」的替换。整理记录删了、库里的文件留着时，再整理会按文件认回来（每个文件都是源文件的硬链接或指向源文件的软链接时）。
- 记成跳过、不整理的：剧集的原盘，一个种子里有几张原盘，原盘里没有视频流，BDMV 或 VIDEO_TS 的上一级就是下载目录或监控目录（原盘没有自己的文件夹；手动整理时选含 BDMV 的那个文件夹）。电影的命名模板没有目录（电影平铺在库目录里）时记成失败，改成先建电影目录的模板（例如默认模板）再整理。
- 升级前跳过的原盘与 ISO 不会自动重新整理（已经有整理记录），在整理历史里点「重试」。

## 触发方式

| 方式         | 说明                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| 自动整理     | pt-tools 推送的种子下载完成后整理。只整理打开以后下载完成的；每 10 分钟补查一次漏掉的                                                 |
| 定期扫描     | 按间隔扫描下载器里已经下载完的种子，不是 pt-tools 推送的也整理。每轮最多 50 个，已经有整理记录的不再扫                                |
| 目录监控     | 整理放进「目录监控」里开着的目录的视频（不是下载器里的种子）：目录里有改动时整理（实时监控），另外按间隔扫描，见[目录监控](#目录监控) |
| 手动整理     | 任务列表里「状态」列的整理图标（手机上是行卡的「整理入库」）；下载器 Web UI 里选中一个下载完的种子后点「整理入库」，或右键菜单        |
| 手动指定路径 | 「整理历史」「媒体库」页的「手动整理」：填一个文件或目录，预览后整理，见[手动整理一个文件或目录](#手动整理一个文件或目录)             |

整理设置里写明定期扫描与目录监控上一次、下一次大约什么时候（这些时间在 pt-tools 重启以后从头算，启动后的第一轮在一分钟内）。

自动整理与定期扫描都只整理「范围」里的种子：下载器、分类、标签、保存路径（下载器里看到的）四项，留空的一项不限制，填了的要满足其中之一。订阅打开了[按条目建子目录](media-subscribe.md#按条目建子目录)时，填的保存路径要包含这些子目录。它们失败以后的自动重试也按现在的设置：关掉了对应的开关，或者种子已经不在范围里，就不再重试。

手动整理先预览：识别出的条目、选中的媒体库、每个文件放到哪里。识别不对时填 TMDB 编号（类型选电影或剧集），也可以换一个同类型的媒体库，点「重新预览」确认后再整理。整理方式默认跟媒体库，也可以在弹窗的「整理方式」里给这一次另选硬链接、复制、软链接或移动（不改媒体库的设置），选了马上重新预览；选移动时还是只整理已暂停的种子。整理过的种子再整理时沿用之前用的条目（预览里写着「沿用之前整理用的条目」）；要换条目，填 TMDB 编号，或先删除整理记录。复制大文件时整理可能要一会儿，弹窗等 20 秒后先关，整理在后台继续，结果到整理历史里看。

同一个文件只整理一次：完成事件重复到达、几种方式同时触发，都不会重复整理。库里已经是这个文件（同一个 inode，或指向源文件的软链接）时直接算完成；目标位置是别的文件时不覆盖，记为跳过（复制与移动出的文件认不出是不是自己放的，目标已存在时一律跳过）；是 pt-tools 之前放的同一条目的旧版本时按媒体库的「同名文件」，见[同名文件](#同名文件)。字幕没整理成时写进记录，下次整理这个种子（重试或再手动整理一次）时补上。

## 目录监控

放进监控目录的视频（不是下载器里的种子，例如手动拷进来的、别的工具下载的）也能按媒体库整理。在媒体库页的「目录监控」里添加目录（pt-tools 里看到的路径），扫描间隔在「整理设置」里改，默认 10 分钟。添加以后路径不能改，要换目录就删掉再添加。

- 实时监控（「整理设置」里的开关，默认打开）：目录里有改动时不等扫描，这一项最后一次改动 2 分钟以后就整理；按间隔扫描照旧进行，实时监控漏掉的照样整理。只在 Linux 与 Windows 上可用，macOS 上只按间隔扫描。加不了监听的目录只按间隔扫描，「目录监控」的列表里写明「实时监控不可用」与原因：inotify 的监听数到了上限（宿主机的 `fs.inotify.max_user_watches`）、目录在 NFS、SMB 或 CephFS 上（收不到别的机器写进来的改动）、一个监控目录里的文件夹超过 4096 个。加不了监听的目录每分钟再试一次。

- 目录下的每一项（一个文件，或一个文件夹）当作一个种子：按它的名字识别，里面的视频按媒体库的方式（硬链接、复制、软链接、移动）放进库里，整理记录里「下载器」一栏写「目录监控」。
- 最近 2 分钟里还有改动的项先不整理（可能还在复制）。每个视频都有整理记录的项不再扫；文件夹里后来多了几集时，整理新的那几集。
- 隐藏的文件与文件夹、NAS 的系统目录（`@eaDir`、`#recycle` 一类）、没下载完的文件（`.part`、`.!qB` 一类）不看。目录超过 6 层或文件超过 5000 个的项整项不整理，整理历史里写明原因。
- 一个位置只有一条整理记录，整理时记下源文件的编号（同一个文件，大小与修改时间也没变才算同一个）：同一个位置上换成了另一个文件（例如移动整理以后又放进来一个同名的），记录管着库里的文件时不整理新的，在那条记录里写明；要整理它，先删除那条记录，下一轮扫描就会整理。记录不管库里的文件（例如识别失败的）时按新文件整理。
- 监控目录不能是媒体库的目录，也不能在媒体库里或包含媒体库；也不要监控下载器的下载目录，那里的种子由自动整理与定期扫描处理。
- 媒体库用移动整理时，先确认这一项不是下载器里的种子（移走了种子就没法做种）：是的话不整理，记录里写明；连不上下载器、确认不了时过一阵再试。种子的路径按「路径映射」换成 pt-tools 里的路径再比；在 pt-tools 里找不到的（没配路径映射，或者下载器在别的机器上）按名字认，和这一项同名的种子当成是它。
- 没有站点给的标题与 IMDb 编号，只按名字识别。认错了时在「媒体识别」里加纠正或识别词，再到整理历史里重试。
- 「删种时一并删除入库链接」不管目录监控整理出的文件：删掉监控目录里的源文件，库里的照样留着。

## 手动整理一个文件或目录

不在 pt-tools 管理的下载器里的视频（例如别的客户端下载的、从别的机器拷来的），可以直接指定它的路径整理进媒体库，不用先加监控目录。在「整理历史」或「媒体库」页点页面上方的「手动整理」：

1. **填源路径**：pt-tools 里看到的一个文件或文件夹，例如一部电影或一季剧集的文件夹，或单个视频文件。在 Docker 里运行时，先把它所在的目录挂进容器，这里填容器里的路径。也可以点「浏览」：先列出能浏览的目录（媒体库、监控目录、路径映射的本地路径、下载器里设的下载目录），点文件夹进去，选一个文件或「选这个文件夹」。只能浏览这些目录，指向它们以外的软链接不列；一个文件夹最多列 2000 项，多了直接填路径。
2. **预览**：点「预览」（或按回车），弹窗写明识别出的条目、放进哪个媒体库、整理方式、写不写 NFO 与图片，以及每个文件在库里的位置。识别不对时选类型（电影或剧集）、填 TMDB 编号，点「重新预览」；也可以换一个同类型的媒体库。TMDB 编号留空就是按名字自动识别。
3. **整理**：按整理方式放进库目录（默认跟媒体库，「整理方式」里可以给这一次另选），媒体库开着刮削时写 NFO 与图片，再通知媒体服务器扫描、发入库通知，和整理种子一样。改了源路径要重新预览才能整理。

**链接放在哪**：就是所选媒体库的目录（打开了「按二级分类放进子目录」时在分类目录里），文件名按媒体库的命名模板。要放到别的目录，先在「媒体库」里加一个库。用硬链接时，源文件与媒体库要在同一个文件系统上，见[准备目录](#准备目录)。

规则：

- 源路径不能是媒体库的目录，也不能在媒体库里或包含媒体库；路径本身不能是软链接，要填它指向的路径。
- 最近 2 分钟里还有改动的不整理（可能还在复制）；目录超过 6 层或文件超过 5000 个的不整理，改选一部电影或一季剧集的文件夹。这两种情况不写整理记录。
- 选单个视频文件时只整理这个文件，同一目录里的字幕不带；要带上字幕就选它所在的文件夹。
- 源路径就是下载器里某个种子的内容时，自动改成按种子整理（预览里写明），整理记录记在这个种子下，删种时清理入库链接、定期扫描都认得它；和下载器里的种子只有一部分重叠（在种子里面或包含种子）时不整理。
- 用移动整理（媒体库用移动，或这一次选了移动）时，源文件会搬进媒体库、不再留在原处：和下载器里的种子同名、或者连不上下载器确认不了是不是种子时不整理，确认不了的过一阵自动再试。还在做种的文件不要用移动整理。
- 也可以填监控目录里的一项，马上整理，不用等下一轮扫描。

失败与重试：

- 每个视频一条整理记录，触发方式写「手动（指定路径）」。
- TMDB 暂时不能访问这类问题按 10 分钟、30 分钟、1 小时、3 小时、12 小时自动重试，最多 5 次；记录里有条目时，自动重试与「重试」都沿用这个条目与当时的媒体库；这一次选过整理方式的也按选的方式，跟媒体库的按媒体库现在的方式。
- 失败或跳过的这种记录还有「手动整理」：带着当时填的路径与选的整理方式打开弹窗，可以换条目、媒体库或整理方式再整理。
- 源路径不在了（删掉或移走了）的记录不再自动重试。
- 手机 App 与 MCP 只能重试这种记录，不能指定新的路径。

手动下载的种子在 pt-tools 的下载器里时，也可以在下载器 Web UI 里选中它点「整理入库」。想让这类种子以后自动整理，在下载器里给它们打上分类或标签，填进「整理设置」的范围，再打开「定期扫描下载器」。

## 导入已有的媒体库

媒体库目录里原来就有的电影与剧集（以前自己整理的、别的工具放进去的），可以导入成整理记录：文件留在原处，不移动、不改名、不建链接。导入以后它们算作库里已有：订阅不再下载这些电影与已有的集，条目详情、日历与追剧详情里写着已入库，洗版按它们的版本比较。

在「媒体库」页的库列表里点这个库的「导入已有文件」：

1. **选路径**：默认是库目录，也可以点「浏览」选库目录里的一个文件夹，只导入它下面的。只能选库目录和它里面的文件夹。
2. **扫描**：点「开始扫描」。每一项都要查 TMDB，扫描在后台进行，弹窗写明认了几项，可以取消。同时只有一次扫描，再开一次时取消上一次；扫描结果留 30 分钟（从最后一次查看算起），过了要重新扫描。
3. **看结果**：每一项写明认出的条目和它从哪来、有几个视频（剧集写明季集）、能不能导入，能导入的默认选上。认错了或没认出来时点「改编号」或「填 TMDB 编号」（类型跟媒体库），改好以后选上。可以只看能导入的、已有记录的或导入不了的；「看视频」列出每个视频与导入不了的原因。
4. **导入**：点「导入 N 项」，排进整理队列（和整理一样一次只做一件），做完写明记下了几个视频、几个已经有整理记录跳过了、几处导入不了与原因。勾着「补上缺的 NFO 与图片」（媒体库开着刮削时才能勾）时，导入完每个条目刮削一次：只写缺的 NFO 与图片，原来就有的不换。

怎么分项：

- 电影库：库目录下每个文件夹是一部电影（里面的视频按[哪些文件会整理](#哪些文件会整理)的规则挑，花絮、样片去掉），库目录下直接放的视频各是一部。
- 剧集库：库目录下每个文件夹是一部剧。季与集按文件名认（套用识别词）；文件名里没写季号时看上面的季目录（`Season 1`、`S01`、`第一季`、`Specials`），都没有时算第 1 季。没认出集数的视频列出来，不导入；直接放在库目录下的视频不导入，要放进剧集的文件夹。
- 名字是二级分类的分类名的文件夹，以及只放着几部电影、几部剧的文件夹（自己分的组）当作分类目录，往下找，最多 4 层。
- 一次最多列 1000 项，多了分子文件夹扫描。一项里目录超过 6 层或文件超过 5000 个、最近 2 分钟里改过视频（可能还在复制；NFO 与图片不算）、原盘（BDMV、VIDEO_TS）、剧集里的 ISO 都不导入，写明原因。
- 已经有整理记录的视频（pt-tools 整理进来的，或之前导入过的）跳过，视频都有记录的一项写「已有记录」。

条目按这个顺序认，认出的类型要和媒体库一样（电影库里认成剧集的不导入，可以改编号）：

1. 已有的 NFO：电影看 `movie.nfo` 与视频同名的 `.nfo`，剧集看 `tvshow.nfo`。写了 TMDB 编号就用它；只写了 IMDb 编号时按 IMDb 编号识别。
2. 文件夹名（库目录下直接放的电影是文件名）里写的编号：Emby、Jellyfin 认的 `[tmdbid=123]`、`[tmdbid-123]`，Plex 认的 `{tmdb-123}`；只写了 IMDb 编号（`[imdbid-tt1234567]`）时按 IMDb 编号识别。编号在 TMDB 上不是这一类时写明，接着按名字认。
3. 按文件夹名识别，和种子名一样套用识别词与纠正。

导入时再读一次每一项的视频，按选定的条目给每个视频记一条整理记录：方式写「已有文件」，触发方式写「导入已有文件」，下载器一栏写「导入」，源文件与库里的文件是同一个。导入的文件不是 pt-tools 放进去的，所以：

- 删除记录时默认不删文件；勾了「同时删除库里整理出的文件」还要再确认一次（批量连文件删除也一样），确认以后按文件编号核对还是导入时的那个文件才删。
- 洗版不删它们：新版本照常整理进库，导入的那条记录不变；文件名不同时两个版本都留在库里。新版本和导入的文件同名时（库里原来的命名和命名模板一样），新版本整理时跳过、留在下载器里；要换成新版本，先在整理历史里连文件删掉导入的那条，再重新整理新版本。
- 「同名文件」选了替换也不替换它们。
- 不用重试：重试与批量重试跳过它们，写明原因。
- 「删种时一并删除入库链接」不处理它们。
- 重新刮削照常可以用：原来就有的 NFO 与图片算别的工具写的，只有开着「覆盖已有的 NFO 与图片」时才换。

## 刮削

打开刮削后，「刮削内容」里可以分别选 NFO、海报、背景图、Logo、Clearart、横幅、横版海报、碟片图（只有电影有）、季海报与集截图（后两项只有剧集有）。没选过的媒体库写 NFO、海报、背景图、季海报与集截图。Clearart、横幅、横版海报与碟片图只有 Fanart.tv 有，在[媒体识别](media-recognize.md#刮削的其它来源)里填了 Fanart.tv 的 Key 才写。

| 条目 | 写的文件                                                                                                                                                                                                                                                                                          |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 电影 | `<文件名>.nfo`（电影有自己的目录、目录里已经有 `movie.nfo` 时写进 `movie.nfo`，不另写一份）；电影有自己的目录时写 `poster.jpg`、`fanart.jpg`、`clearlogo.png`、`clearart.png`、`banner.jpg`、`landscape.jpg` 与 `discart.png`，放在库目录根下时这些图片前面加上文件名，例如 `<文件名>-poster.jpg` |
| 剧集 | 剧集目录里的 `tvshow.nfo`、`poster.jpg`、`fanart.jpg`、`clearlogo.png`、`clearart.png`、`banner.jpg`、`landscape.jpg`、`season01-poster.jpg`（第 0 季是 `season-specials-poster.jpg`）；季目录里的 `season.nfo`；每集的 `<文件名>.nfo` 与 `<文件名>-thumb.jpg`                                    |

Logo 是透明背景的片名图，Clearart 是透明背景的人物与片名图，横版海报是带片名的横图；这些文件名 Emby、Jellyfin 与 Kodi 都认。「图片语言」决定用哪一张：

| 图片语言           | 海报                                     | 背景图           | Logo 与其它                      |
| ------------------ | ---------------------------------------- | ---------------- | -------------------------------- |
| 跟识别语言（默认） | 来源默认的那张（TMDB 按识别语言给的）    | 来源默认的那张   | 依次找识别语言、英文、没有文字的 |
| 中文、英文、日文   | 优先用这种语言的，没有时用来源默认的那张 | 优先用没有文字的 | 依次找这种语言、识别语言、英文   |
| 无文字             | 优先用没有文字的                         | 优先用没有文字的 | 依次找没有文字的、识别语言、英文 |

要写 Logo 或选了图片语言时，pt-tools 会多取一次 TMDB 的图片列表（缓存一周）。取不到时海报与背景用 TMDB 给的那张、不写 Logo，整理结果里写明原因。集截图总是用 TMDB 给的那张。

NFO 是 Kodi 格式，Emby、Jellyfin 与 Plex 的 NFO 插件都认。里面除了标题、简介、类型与评分，还有宣传语、分级、出品公司（剧集是电视网）、电影所属的系列、剧集的状态、导演、编剧与演员（头像是 TMDB 的图片地址），以及 TMDB、IMDb、TVDB、豆瓣与 Bangumi 的编号（有哪个写哪个）。图片走媒体识别里设置的代理下载，同时下载三张。模板把每集平铺在库目录根下时，不写剧集与季的文件。

勾选「演员名用中文」时，NFO 里前 15 位演员的名字用 TMDB 上的中文译名（依次找 `zh-CN`、`zh-SG`、`zh-TW`、`zh-HK` 的译名），没有译名的用原名，角色名不变；译名缓存 30 天。取不到译名时用原名，刮削结果里写明。

刚播出的一集整理入库时，TMDB 上常常暂时没有这一集的标题、简介与截图：NFO 照样写（标题写「第 N 集」），记成部分刮削。部分刮削与刮削失败的记录在整理以后的第 1、3、7、14 天各自动补刮一次，不用打开下面的每周补刮：一部电影或剧集排一次，只补没有的文件，pt-tools 写的 NFO 换成新的，自己放的、别的工具写的文件不换；每个库一次最多 50 个条目，先补刮削得最早的。

勾选「每周补一次缺的刮削」时，每 7 天把这个库里刮削结果是部分刮削或刮削失败的条目重新刮削一次，一次最多 50 个条目，先补刮削得最早的（过了第 14 天还缺的也补）。和「重新刮削」一样，只是不管开没开覆盖，自己放的、别的工具写的文件都不换。整理队列满了时这一轮没排上的下次再补。

已经有的文件默认不动，打开「覆盖已有的 NFO 与图片」后重写：

- 重写 NFO 时只换 pt-tools 写的那几项，别的原样留着，例如媒体服务器写进去的播放记录、添加日期、标签与媒体信息。
- Jellyfin 与 Emby 里锁定了的条目（NFO 里有 `<lockdata>true</lockdata>`）不改；锁定了的字段（`<lockedfields>`，例如简介、类型、演员）用原来的。
- 内容和已有的一样时不重写，媒体服务器不会因此重新读取。
- 写之前再看一次文件：取数据的这段时间里文件被改了、新放了或锁定了，就不换。

### 数据来源

NFO 与图片默认都用 TMDB 的。「数据来源」可以按项换成别的来源，选的来源找不到这部、没有这一项或者暂时不能访问时用 TMDB 的，整理结果与[整理历史](#整理历史)里写明原因：

| 项目   | 可以选                    | 说明                                                                                                             |
| ------ | ------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 简介   | TMDB、豆瓣、Bangumi       | 电影、剧集与每一季的简介。豆瓣与 Bangumi 上剧集一季是一个条目：`tvshow.nfo` 用第 1 季的，`season.nfo` 用这一季的 |
| 评分   | TMDB、豆瓣、Bangumi、IMDb | 主要的评分。取到的其它来源的评分也写进 NFO，主要的写在最后：Jellyfin 与 Emby 显示最后一个                        |
| 每一集 | TMDB、Bangumi             | 每一集的标题与简介（只有剧集有）。TMDB 上没有的集用 Bangumi 的补上                                               |
| 图片   | TMDB、Fanart.tv           | 海报、背景、Logo 与季海报先用哪个来源的；第一个来源没有这种图、或者它的图下载不了时用另一个的                    |

- 豆瓣：写 NFO 前按中文名在豆瓣上找同一部，找不到再用原名找：名字对得上的里面年份相同的优先，没有时差一年以内的只有一个才用；同名的不止一个、拿不准时用 TMDB 的。剧集按季找，第 2 季起按这一季首播的年份。pt-tools 推送的种子带着站点给的豆瓣编号时，电影先按编号取，名字与年份都对得上才用。
- 豆瓣没有开放的接口，pt-tools 用的是豆瓣网页自己用的两个（搜索与条目详情），不登录豆瓣，不走媒体识别的代理。每 2 秒最多请求一次豆瓣；搜索结果缓存一天，条目缓存一周。
- Bangumi：只用于动画（TMDB 类型里有「动画」的条目），别的条目用 TMDB 的。按原名与首播日期找同一季，日文的简介与标题不用。用的是 Bangumi 的开放接口，不用 Key，每秒最多请求一次。
- IMDb：评分经 OMDb 取，要在[媒体识别](media-recognize.md#刮削的其它来源)里填 OMDb 的 Key。填了以后不管这里选没选，NFO 里都会写上 IMDb、烂番茄与 Metacritic 的评分（按 IMDb 编号查，TMDB 上没有 IMDb 编号的不查）；TMDB 上没有分级时用 OMDb 的。
- Fanart.tv：要在媒体识别里填 Fanart.tv 的 Key。电影按 TMDB 编号找，剧集按 TVDB 编号找（TMDB 上没有 TVDB 编号的剧集用 TMDB 的图片）。没选 Fanart.tv 时，Logo 先用 TMDB 的，TMDB 没有时用 Fanart.tv 的。
- 只为这次要写的文件去取：已经有的 NFO 不覆盖时不去找豆瓣与 Bangumi。改了数据来源以后，已经整理的条目在整理历史里点「重新刮削」就会换。

## 字幕

种子里的字幕跟着视频一起整理（见[哪些文件会整理](#哪些文件会整理)）。种子里没有字幕时，还可以到站点上取，或者交给 ChineseSubFinder 下载：在媒体库设置的「字幕」里打开。

### 站点字幕

勾选媒体库的「整理完到站点上下载字幕」后，新放进这个库的视频满足下面几条时，pt-tools 到种子的详情页取站点上的字幕：

- 种子里没有字幕文件；
- 种子是 pt-tools 推送的（RSS、搜索、订阅与追剧、qB 兼容入口推送的都算），记着是哪个站点的哪个种子；
- 站点是 NexusPHP 架构的：一个种子的字幕在详情页「字幕」那一行（`downloadsubs.php` 的链接）。站点改过详情页、页面上找不到这种链接时，当作站点上没有字幕。别的架构的站点不取。

取哪些、放在哪：

- 列表上有中文的（简体、繁体或没分简繁的中文）只取中文的，没有中文的时候都取；语言按列表上写的语言、国旗图与标题认。一个种子最多下载 10 份。
- 种子里有几个视频时，按文件名前缀或季集分给对应的视频；看标题就知道对不上哪个视频的不下载，以前整理过的那几集不再放。
- zip 压缩包解开只取字幕文件（名字不是 UTF-8 时按 GBK 认；只取文件名，不按包里的目录放）；rar 与 7z 不解，整理历史里写明。
- 放成「视频名.语言.后缀」，同种子里的字幕，例如 `奥本海默 (2023) - 2160p BluRay HDR H.265.zh-CN.srt`；同一种语言有几份时第二个起加 `.2`、`.3`。名字已经被别的文件占着时换下一个序号，不覆盖。一个视频最多放 4 个。
- 请求走站点的限速与重试，和这个站点别的请求共用；站点设置里要填好 Cookie。

放进去的字幕记在整理记录里，整理历史的「N 个字幕」算上它们，[删除](#整理历史)时一起删（按文件编号确认，换过的留着）。取不到列表、下载失败、压缩包解不开这类问题写在这条记录的说明里，不影响整理的结果。重新整理时，以前放的站点字幕还在就不再取。

### ChineseSubFinder

[ChineseSubFinder](https://github.com/ChineseSubFinder/ChineseSubFinder) 是自动下载中文字幕的工具。在媒体库里填好下面几项，新整理出的视频（原盘除外）就交给它下载字幕：

| 设置                        | 说明                                                                                          |
| --------------------------- | --------------------------------------------------------------------------------------------- |
| ChineseSubFinder 的地址     | 例如 `http://192.168.1.10:19035/`；空着是不用，保存时一起清掉 API Key                         |
| API Key                     | 在 ChineseSubFinder 的「实验室」设置里打开 API Key；只写不读，保存后显示「已设置」            |
| ChineseSubFinder 里的库目录 | ChineseSubFinder 那边看到的这个库的路径（两边在不同的容器里时多半不一样）；和库目录一样时空着 |

「测试」访问一次 ChineseSubFinder，确认地址与 API Key，不建任务；没重新填 Key 时用保存的。

- pt-tools 调 ChineseSubFinder 的 `api/v1/add-job` 接口，每个视频一个任务，优先级 3（ChineseSubFinder 自己扫到的是 5）；视频的路径按「ChineseSubFinder 里的库目录」换成它那边的路径。
- 交给它是在刮削之后：剧集要开着刮削，ChineseSubFinder 读每一集的 NFO。
- 交不上（连不上、Key 不对、它那边找不到文件）写在这条记录的说明里，不影响整理的结果。连不上或 Key 不对时，这一批后面的视频不再试。
- 字幕由 ChineseSubFinder 下载、放进库里，不记在 pt-tools 的整理记录里，删除记录时不删。

## 媒体服务器

整理完通知媒体服务器扫描新目录；同步过索引的服务器，条目详情里写明这一部在服务器里有没有、能直接点进去播放。不加媒体服务器也能整理，媒体服务器会按自己的计划扫描。

| 项目                       | 说明                                                                                                                      |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 种类                       | Emby、Jellyfin 或 Plex                                                                                                    |
| 地址                       | 完整的地址，如 `http://192.168.1.10:8096`（Plex 是 `:32400`）。媒体服务器回跳转时不跟着跳                                 |
| API Key                    | Emby、Jellyfin 在控制台的「API 密钥」里新建；Plex 填 X-Plex-Token。加密保存，只写不读                                     |
| 刷新方式                   | 只扫整理到的目录（默认），或刷新整个媒体库                                                                                |
| 路径前缀                   | 媒体服务器看到的路径与 pt-tools 不同时填两边的前缀，比如 pt-tools 的 `/media` 在 Emby 里是 `/data/media`                  |
| 打开链接用的地址           | 详情页「在 Jellyfin 播放」打开的地址。上面的地址浏览器打不开（比如容器里的名字 `http://jellyfin:8096`）时填，不填用上面的 |
| 索引间隔（小时）           | 多久同步一次[索引](#索引)，默认 6，最多 168；填 0 关闭索引                                                                |
| 继续观看的用户             | Emby、Jellyfin 才有：点「读取用户」从服务器读出用户再选，首页的继续观看列这个用户没看完的（见[继续观看](#继续观看)）      |
| 把服务器里有的集算作已入库 | 默认关，见[算作已入库](#算作已入库)                                                                                       |
| Webhook                    | 编辑已经保存的服务器时生成地址，见 [Webhook](#webhook)                                                                    |
| 播放通知                   | 选通道以后，Webhook 发来开始播放、停止播放时发通知，见[播放通知](#播放通知)                                               |

点「测试」确认地址与 API Key 能用。列表里写着最近一次通知的结果与索引的情况；通知失败不影响整理。填了路径前缀而整理到的目录不在里面时，不把 pt-tools 的路径发给这个服务器，列表里写明原因。

Jellyfin 只扫整理到的目录时，空的媒体库整理进第一部片子以后，要在 Jellyfin 里扫一次这个库。Jellyfin 按路径往上找它认识的目录，媒体库的目录要等里面有片子、扫过一次以后才认识（空着时扫也不算）；在这以前什么也不刷新，Jellyfin 的实时监控也不看这个目录。扫过一次以后，整理进来的会自己出现。

### 索引

索引记下服务器里有哪些电影、剧集与每一集（TMDB、IMDb、TVDB 编号与文件路径），用在：

- 条目详情的「你的 NAS 上」第 4 行与「在 Jellyfin 播放」，剧集每一集的播放按钮（见[条目详情](media-detail.md#你的-nas-上)）；
- 首页的继续观看，剧集按索引找到是哪一部；
- [算作已入库](#算作已入库)。

同步的规则：

- 启用的服务器按「索引间隔」整个同步一遍；pt-tools 启动 1 分钟以后同步从没同步过的服务器。列表里点「同步」马上同步，等同步做完。
- 开了 [Webhook](#webhook) 时，服务器报新入库或删除以后 2 分钟同步这一台，2 分钟里再来的合进同一次。
- 拉全了才写：拉到一半失败、超过 10 分钟或超过 20 万项时这一次什么也不写，列表里写明原因，30 分钟以后再试。同步的时候服务器里的条目有增减（分页可能错位）时，这一次只写新加与改了的，不标删除，下一次再算。
- 服务器里没了的项先标成删除，90 天以后才清掉；改了种类或地址、或者服务器的编号变了（换了一台服务器）时，先清掉这一台旧的索引再同步。
- 文件路径按上面的路径前缀换成 pt-tools 的路径；换不了的只记服务器里的路径。

### 服务器里没了的片子

pt-tools 整理进库的电影或剧集的某一集，在服务器里没了（被删了，或者库里的文件不见了，服务器扫描以后去掉了），同步时记一个问题：

- 条目详情的「你的 NAS 上」第 4 行用警示色写 `S02E03 在服务器里被删了`，这一集的集卡写 `Jellyfin 里没有了`；
- 点「处理」打开只选这几集的删除弹窗（见[删除一部片](media-detail.md#删除一部片)），删掉库里的文件与整理记录以后问题改成已处理；在整理历史里删掉记录、洗版换掉这个版本时也一样；
- 点「忽略」不再提示，这一项一直没再出现时都不提示；服务器里又有了的，问题自己关掉。

对应的整理记录先按路径找（服务器里的路径换成 pt-tools 的路径以后，等于整理记录的目标路径）；换不了路径时电影按 TMDB 编号、剧集按 TMDB 编号与季集找。不是 pt-tools 整理的不记。

### Webhook

开了 Webhook，服务器有新入库、删除与播放时告诉 pt-tools：新入库与删除 2 分钟后同步这一台的索引，开始与停止播放发[播放通知](#播放通知)。Webhook 本身不改索引，也不删任何东西。

编辑服务器，在「Webhook」点「生成地址」。地址只显示这一次，形如 `http://<pt-tools 的地址>/api/media/servers/1/webhook/<令牌>`；媒体服务器访问 pt-tools 的地址和浏览器不同（比如在 Docker 里）时，把前面的地址换掉。「重新生成地址」以后原来的地址作废，「关掉」以后一律不认。令牌只存摘要，日志里打码。每台服务器每分钟最多收 60 次，请求体最多 1 MiB。

在媒体服务器里填这个地址：

| 服务器   | 怎么填                                                                                                                                                                                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Jellyfin | 在「控制台 → 插件 → 目录」装 Webhook 插件，重启以后在插件设置里「Add Generic Destination」：Webhook Url 填这个地址，Notification Type 勾 Item Added、Item Deleted、Playback Start、Playback Stop，Item Type 勾电影、剧集与集，勾上 Send All Properties（不用写模板） |
| Emby     | 在「设置 → 通知」（Webhooks）里加这个地址，事件选新媒体、删除、开始与停止播放；数据类型选 application/json 或表单都行                                                                                                                                                |
| Plex     | 在「设置 → Webhooks」里加这个地址（要 Plex Pass）                                                                                                                                                                                                                    |

Jellyfin 的 Webhook 插件把新入库与删除攒起来，大约每一分半钟发一次（开始、停止播放马上发）。算上 Jellyfin 自己攒 1 分钟的改动再扫描、pt-tools 收到以后等 2 分钟，整理进库的片子三到五分钟以后进索引。刚装好插件时要等得更久：插件发这两种通知的两个计划任务从没运行过时，Jellyfin 启动 1 小时以后才第一次运行。不想等，在 Jellyfin 的「控制台 → 计划任务」里运行一次 Webhook Item Added Notifier 与 Webhook Item Deleted Notifier，再重启 Jellyfin。插件攒着的通知只在内存里，Jellyfin 重启时没发出去的就没了，按「索引间隔」的定时同步会补上。

列表与弹窗里写最近一次收到的时间与事件，可以用来确认服务器发过来了。服务器关着（没启用）时收到的 Webhook 只记下来，不处理。

Jellyfin 12.2 与 Webhook 插件 22.0.0.0 做过真实验证；Emby 与 Plex 只按它们的文档与请求样本测过。

### 继续观看

在服务器设置里选「继续观看的用户」，[首页](home-and-health.md#继续观看)显示这个用户在 Emby、Jellyfin 里没看完的电影与剧集（每台最多 12 项），剧集写季集与集名、带剧照，点了在服务器里打开。媒体库页的服务器列表里写有几项。Plex 没有这一项。

哪些算没看完按服务器自己的规则：Jellyfin 默认只记片长 5 分钟以上的播放进度，看了不到 5% 算没看、超过 90% 算看完。一集只有几分钟的短剧要在 Jellyfin 的「控制台 → 播放 → 恢复播放」里把「恢复播放的最短时间」调小。

### 播放通知

在服务器设置里选「播放通知」的通道以后，Webhook 发来开始播放、停止播放时发一条，例如：

```text
▶️ 开始播放：最后生还者 S01E01「当你迷失在黑暗中」
Jellyfin · admin · Living Room TV（Jellyfin Web）
```

同一部再播一次也会发；剧集的集名就是文件名（服务器没取到元数据）时只写剧名与季集。通知和别的后台通知一样排队发出，最多晚 1 分钟；按通道的静默时段延后，失败时自动重试；文字可以在[消息模板](notify-channels.md#消息模板)里改，事件是 `media.playback`。没选通道时不发。

### 算作已入库

打开「把服务器里有的集算作已入库」以后，追剧时这台服务器里有的集算已入库：整理记录里没有、服务器里有的集，在追剧详情与条目详情里写已入库（来源是媒体服务器），不再下载。适合在 pt-tools 以外放进媒体库的片子。

- 只对剧集的每一集。电影不看这个选项：没开洗版的电影订阅本来就会问媒体服务器里有没有这一部。
- 开着洗版的订阅，这些集按没有版本算（pt-tools 不知道服务器里的文件是什么版本）：搜到符合质量档案的整季包时照样下载、整理进库，服务器里原来的文件不动，会多一份。不想这样时别给这部剧开洗版。
- 关掉选项、关掉服务器或关掉索引以后，这些集又算缺。

## 入库通知

在「整理设置」里选择通道后，每次有新文件入库时发一条：标题与年份、季集、画质、媒体库、来源种子，最后是 TMDB 的海报地址（Telegram 一般会把它显示成预览图）。通知按通道的静默时段延后，失败时自动重试。没有选通道时不发。

## 整理历史

每个视频文件一条记录，写明整理成哪个条目、条目从哪来（见[哪些文件会整理](#哪些文件会整理)末尾的顺序；升级前的记录不写）、整理到哪里、用什么方式、哪种方式触发、成功还是失败，以及上一次刮削的结果：刮削成功、部分刮削（选了的有的没写成：来源里没有、下载失败或者没填 Fanart.tv 的 Key；剧集的一集来源里暂时没有集标题或集简介；或有来源出错、用了 TMDB 的）或刮削失败，下面一行写明原因与说明。

| 状态   | 说明                                                                                                                                                                |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 已整理 | 文件已经在库里                                                                                                                                                      |
| 失败   | 写明原因。TMDB 暂时不能访问这类问题按 10 分钟、30 分钟、1 小时、3 小时、12 小时自动重试，之后不再自动重试；没识别出来、不在同一个文件系统这类要先改设置的不自动重试 |
| 跳过   | 目标位置已经有别的文件，没有可整理的视频，整理不了的原盘（见[原盘](#原盘)），或者剧集里的 ISO                                                                       |
| 已删除 | 库里的文件已经删掉                                                                                                                                                  |

失败与跳过的记录写明分类：没识别出来、媒体库（没有启用的库、命名模板或二级分类的问题）、路径映射（pt-tools 里找不到文件）、文件系统（不在同一个文件系统、没有权限）、目标已有文件、源文件不在了、原盘与镜像（整理不了的原盘、剧集里的 ISO）、其他。升级到这个版本以前的失败、跳过记录没有分类，算其他。看全部、失败或跳过时可以按分类筛选。

勾选几条记录以后，列表下面出现批量操作：

- **重试**：只重试勾选里失败、跳过的；同一个种子（或监控目录的同一项、同一个路径）的几条只整理一次。
- **重新刮削**：只刮整理好的；同一个媒体库里的同一部只刮一次。
- **删除记录**与**连文件删除**：先确认；连文件删除的规则同下面的「删除」，移动整理的那几条只能删记录，结果里写明。

重试与重新刮削排进整理队列就回，稍后刷新看结果；结果里写明成了几条、没做成的原因。

「按条目」把记录按电影、剧集的一季分组（没识别出来的按种子名），写明每组几条、各状态几条与最近的时间，状态、分类与关键字的筛选照样生效；点「看记录」看这一组的记录，「返回分组」回去。

[导入的已有文件](#导入已有的媒体库)的记录方式写「已有文件」、触发方式写「导入已有文件」，不能重试；连文件删除时要再确认一次。

没识别出来的记录有「让 AI 认」：打开整理弹窗，预览以后马上让 AI 认一次，见[让 AI 认](#让-ai-认)。

「重试」重新整理这条记录所在的整个种子；改了识别词、加了纠正或媒体库之后点它。手动整理时选过整理方式的，重试还按选的方式。失败、跳过的「手动（指定路径）」记录还有「手动整理」：打开弹窗，带着当时填的路径与选的整理方式，可以换条目、媒体库或整理方式再整理。

「重新刮削」按媒体库现在的刮削设置，重写这条记录所在的电影或剧集（这个媒体库里同一部整理好的每一集）的 NFO 与图片；改了刮削内容、数据来源、图片语言，或者在媒体识别里填了新的 Key 之后点它：

- pt-tools 刮削时写的、之后没被改过的文件换成新的（没开覆盖也换）；自己放的、别的工具写的只在开着「覆盖已有的 NFO 与图片」时换；锁定了的 NFO 不动；没有的补上。内容和原来一样的不重写；因为改过或锁定了而没换的文件，结果里会列出来。
- 各来源都不读缓存，取它们现在的数据（取到的照样写进缓存）。
- 只刮削库里的视频还是当初整理出的那个的记录：视频不在了或者换成了别的文件时不写，记成刮削失败并写明原因。
- 和整理一样排队，一次只做一件；等不到结果时先回，稍后刷新看。
- 升级到这个版本以前整理的记录没记着放进了哪个分类目录：媒体库按二级分类放进子目录、又认不出它在哪个分类目录里时不刮削，结果里写明。

「删除」时可以勾选「同时删除库里整理出的文件」：视频与字幕只删确认还是当初整理出的那个文件（硬链接与复制按文件编号确认，包括设备、inode、大小与修改时间；软链接按指向确认）；NFO 与图片只删 pt-tools 刮削时写的那份，目录里的海报、背景、Logo 与 NFO 等目录里不再有视频时才删；最后删空目录。换掉或改过的文件留着，删除后会列出来。记录变成跳过或失败（例如库里的视频被换成了别的文件）时，之前整理出的字幕与刮削写的文件仍记在这条记录里，删除时照样按上面的规则清理。移动整理的文件是唯一的一份，这里不删。下载目录里的文件都不动。

## 库里的文件不见了

pt-tools 每天巡检一次整理好的记录，看库里的文件还在不在（硬链接、复制的看文件本身，软链接还要看指向的文件，原盘看主文件）。不见了的记一个问题：

- 条目详情的「你的 NAS 上」第一行用警示色写 `S02E05 的文件不见了`，这一集的集卡写 `库里的文件不见了`；
- 点「处理」打开只选这几集的删除弹窗（见[删除一部片](media-detail.md#删除一部片)），删掉整理记录以后问题改成已处理；
- 点「忽略」以后，文件回来以前都不再提示；文件又有了，问题自己关掉；整理记录删掉了，或者不再是已整理的，问题也关掉。

巡检只记问题，不删任何东西。从没巡检过时启动 10 分钟以后第一次，之后每 24 小时一次，重启以后按上一轮的时间排；一轮最多查 5000 条记录，多的下一轮接着查。媒体库目录不在（例如没挂载）或者媒体库删了的记录不查，不会当成文件丢了。

## 让 AI 认

种子名认不出条目时（整理弹窗的预览写「没有识别出来」，整理历史里分类是「没识别出来」），可以点「让 AI 认」：pt-tools 按种子名在 TMDB 上搜电影与剧集（套用识别词，不看纠正，最多 8 个候选），连同种子名、站点上的标题发给 [AI 助手](./assistant.md)的模型，让它挑一个或者说都不是。

- 认出以后，类型与 TMDB 编号填进「识别不对」那一行，预览按这个条目算，写明 AI 的理由、用的模型与 token 数。**整理还是要自己点**，可以先看预览、改条目或媒体库。
- 勾着「整理时记成纠正」（默认勾着）时，点「整理」先存一条[纠正](./media-recognize.md)，以后名字一样的种子直接认成这个条目；改了「识别不对」里的条目就不记。
- AI 说都不是时列出前几个候选，可以自己填 TMDB 编号。TMDB 上搜不到候选时不调模型。
- 要先在「AI 助手」里启用并配好接口地址、Key 与模型；没配好时写明原因。一次最多等 30 秒。
- 发给模型的只有种子名、站点上的标题和候选的类型、名字、年份与简介的前 80 个字，像密钥的长串先遮掉；用的是 AI 助手的接口，不带工具，不会整理或改动别的东西。

## 与自动删种的关系

硬链接入库以后，删掉种子连数据也腾不出空间（库里的链接还占着），所以低空间紧急清理不挑已经硬链接入库的种子。常规的删种规则照常生效：做种够了删种，库里的文件照样能看。

「删种时一并删除入库链接」默认关闭。打开后，种子已经不在下载器里、源文件也没了（连数据删掉了）时，pt-tools 每 10 分钟检查一次，删掉从它整理出的硬链接与软链接，记录改成「已删除」；复制与移动的文件不删。打开以后，紧急清理也会挑硬链接入库的种子，删掉以后空间才腾得出来。种子的保存目录或库目录不在（例如没挂载）、下载器连不上时不做任何删除。

在条目详情的[删除弹窗](media-detail.md#删除一部片)里连数据删种子、库里的文件没勾删时，这个种子整理出的硬链接就是你要留着的：这些记录记一个标记，「删种时一并删除入库链接」不删它们。同一个源文件以后重新整理进库时，标记去掉。

## 常见问题

**整理失败：源文件与媒体库不在同一个文件系统**：硬链接要求下载目录与媒体库在同一个分区。Docker 里按[准备目录](#准备目录)挂载成同一个卷，或者把媒体库改用复制。

**整理失败：pt-tools 里找不到某个路径**：下载器与 pt-tools 看到的路径不同，在「路径映射」里添加对应关系，再在整理历史里重试（可以按「路径映射」筛出来一起重试）。重试时找得到文件了，之前按下载器的路径记下的那几条失败记录就自动删掉。

**没有识别出来**：到[媒体识别](media-recognize.md)里预览这个种子名，选候选或填 TMDB 编号纠正，再回到整理历史点「重试」；也可以手动整理时直接填 TMDB 编号，或者[让 AI 认](#让-ai-认)。

**目标位置已经有同名文件**：pt-tools 不覆盖别的文件。确认库里那个文件不要了，删掉后重试。

**以前自己整理的媒体库，订阅还会再下载一遍**：订阅只认整理记录。在「媒体库」里点「导入已有文件」，把库里原来的电影与剧集记成整理记录，见[导入已有的媒体库](#导入已有的媒体库)。

**手动下载的电影怎么整理、链接放在哪**：见[手动整理一个文件或目录](#手动整理一个文件或目录)。

**开了站点字幕却没有字幕**：看整理历史里这条记录的说明：写着「站点上没有这个种子的字幕」的是站点上确实没有（或者站点改过详情页）；什么都没写的，多半是种子里本来就有字幕、种子不是 pt-tools 推送的，或者站点不是 NexusPHP 架构的，见[站点字幕](#站点字幕)。
