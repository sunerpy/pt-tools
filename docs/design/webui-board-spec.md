# Web UI 画板规格（Penpot 页面 G Cockpit）

来源：Penpot file `d8ac01df-6646-81d2-8008-9ee2385f8df4` / page `G Cockpit`
`f71c3c8c-a81d-80a2-8008-a3fa6d0e51a1`，共 44 个画板。**所有数值都是通过 Penpot MCP
读回来的，不是估算。**

这份文档是画板的转写，代码按它落地。可执行的那一半在
`web/frontend/scripts/board-check.mjs`：它把每条路由该有的带与栏宽写成断言，
拿真实渲染去比，不一致就退非零。文档与脚本对不上时，以画板为准，两边一起改。

偏离表（§5、§7）是给 owner 复核用的：每一条都是「画板有、落地没有」或者
「落地和画板不一样」，写清原因。想让检查通过，先实现它，不是往偏离表里加一行。

## 3 与现实现的结构性差异（用户所说「差别很大」的主因）

1. **每页都有 88 高面包屑页头** → 应为 64 高「标题 + 实时摘要」；面包屑只属于详情页。
2. **主区有 16/24/32 内边距且一切都在卡片里** → 应为全宽带；卡片只用于表格下方的分析面板。
3. 表格被包在圆角描边卡片里 → 应全宽平铺，且**列间有竖线**、表头下沿用 borderStrong。
4. 工具栏、表格页脚、多选条都不是独立带。
5. KPI 条不是 6 格全宽带（缺格间竖线、变化 pill、48×22 柱图）。
6. rail / nav 的激活指示、节奏、徽标、账号页脚与版本行均不符（见上表）。
7. 状态栏缺右端下载器身份格；调度器格未用 ok 绿。

## 5 落地偏离（画板 vs 实现，供 owner 复核）

1. 画板总览页没有页头，导航收起开关原本在页头里 → 开关移到 rail（它控制的是导航列，
   属于外壳）。画板 rail 没画这个开关，属新增。
2. v2 升级横幅画板未在任何路由构成里给它位置 → 按卡片层处理（内缩 16，置于内容顶部）。
   关掉之后页面与画板一致。
3. 页面自带的可关闭提示 → 按画板 27 的落法放在顶部带之后、内缩 16。
4. 默认明暗：画板是浅色内容，故默认改为明亮（原为黑暗）。用户选过就记住。
5. 状态栏右端画板是「qb-main · 已连接 · v2.9.3」；下载器客户端版本后端未暴露，
   先落「名称 · 连接态」，版本待后端补字段。

### 新增偏离（画板有、落地没有，供 owner 复核）

⑥ 卡片上下间距按 16 统一。画板多数页是 16（27 系统设置 head 64 → warn 80），
   但 17 暂停任务是 20（c-paused 84）、13 站点详情是 16（144 - 128）。取 16。

⑦ 后端没有数据源、因此没有实现的分析卡：
   - 29 运行日志左栏 p-files / p-lv / p-arc（文件清单 / 级别筛选 / 归档）
   - 28 CloakBrowser 的 p-res（探测结果）与 p-life（会话生命周期）
   - 19 下载器设置的 p-dir / p-safe / p-bind / p-log —— 对应的是全局设置里的下载目录、
     磁盘保护、站点绑定与日志，本页不重复一份
   - 各带式页 gfoot 之后的 p-* 分析卡（p-up / p-dist / p-thr / p-hit …）
   这些不是版面问题，是需要新接口才能填的内容。

⑧ 13 站点详情画板有 6 个分区（概览 / RSS 订阅 / 任务 / 推送记录 / 过滤规则 / 凭据）。
   任务与过滤规则在本项目是独立路由（/tasks、/filter-rules），推送记录没有接口，
   凭据画板自己放在右栏常驻卡里而不是一个分区 —— 所以分区带只有「概览 / RSS 订阅」两项。
   画板 head 的 sub 写的是分享率/上传/做种，那几项属于用户数据接口，不在站点配置里，
   落的是「域名 · 认证方式 · RSS 条数」。画板的 tag「NexusPHP」SiteConfig 里没有这个字段。

⑨ 15 种子搜索：画板 bar-88 有一条「全部/电影/剧集/动漫/音乐」的全局分类分段，
   但本项目的分类是各站自己的（工具栏里那些分类 chip），没有跨站统一口径，故未实现。
   画板 search-head 右侧的 history / 保存搜索两枚动作同样没有后端，未实现。
   画板 facet 那排是「站点 / 类型 / 排序 / 仅免费」，落的是站点 / 排序 / 方向。

⑩ 20 过滤规则画板有 bar-64，但这一页没有任何筛选控件，空带没有意义，未加。

⑪ 18 下载器 Web UI 画板有 bar-64（head 之后 40 高的独立带），落地把那条工具栏留在
   任务列表卡的内部（十来个控件，拆出去会和卡头叠成两层标题），所以 p-grid 的 y 是 80
   而不是画板的 120；x 与宽度（636 / 788）与画板一致。

## 8 第三轮落地（补齐分析卡、加可失败的验收）

上一轮把版面构成对齐之后，Codex 的完成度评审指出两件事：画板上大量分析卡整组缺失，
而当时的验收脚本只在「横向溢出」或「出现未解析组件」时失败，缺卡、错分栏、错坐标
都能拿到绿灯。两条都对，这一轮就是回应它们。

### 可失败的验收

`web/frontend/scripts/board-check.mjs`：21 条路由（含两条详情路由）逐条量，
`EXPECT` 写画板该有的带与栏宽，`ALLOWED_GAPS` 写明确记下来的偏离。
不在偏离表里的缺失一律失败，偏离登记多余（其实已经对上了）也失败。
控制台报错同样算不一致 —— 渲染崩了页面照样量不出东西，得说清是崩了还是没做。

`web/frontend/scripts/board-fixtures.mjs` 喂假数据：画板的页脚带、多选条和一部分卡
只有有数据时才渲染，拿空库去量会把「没实现」和「没数据」混成一件事，那就又变成了
一个永远绿灯的验收。

跑法（前端 dist 必须是当前源码构建出来的）：

```bash
pnpm --dir web/frontend build && CGO_ENABLED=1 go build -o /tmp/pt-tools . \
  && /tmp/pt-tools web --host 127.0.0.1 --port 18260 &
node web/frontend/scripts/board-check.mjs http://127.0.0.1:18260
```

### 这一轮修掉的两个缺陷

1. **多根节点导致跳转白屏。** `App.vue` 的 `<router-view>` 外面套着
   `<transition name="fade" mode="out-in">`。路由组件有多个根节点时 Transition
   认不出要过渡的元素，`out-in` 的 leave 回调不触发，**下一个页面永远不挂载** ——
   主区一片空白，控制台一句报错都没有。修改密码页补三张说明卡时中过这个。
   钉子：`src/views/views.root.test.ts` 用 `@vue/compiler-sfc` 解析模板 AST，
   逐个页面断言只有一个根节点（`v-if` 链算一个）。
2. **任务列表的组合筛选被改没了。** `downloaded / pushed / expired` 三个参数在
   `apiTasks` 里是逐个 AND 进查询的，「已下载 + 已推送」是「推成功了的」这个真实
   且常用的组合。改版中途把它们收成了互斥单选的分段器，等于删掉了组合筛选能力。
   现在恢复成三个可叠加的 chip（画板 toolbar 的 chip 就是筛选位）。
